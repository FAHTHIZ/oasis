Built for the things people hate about coding agents.

Most agent failures are harness failures. OASIS fixes each one in the runtime, so the fix holds whichever model you connect.

It said it was done, but never ran the tests.

A verification gate: the agent must review its diff and run a relevant check before it can finish. Any later edit resets it.

It ran rm -rf while I wasn't watching.

Catastrophic commands are refused even with approvals off, including when hidden in bash -c, eval or $(…). High-risk ones always ask.

It changed the test to match the broken code.

Weakened-test detection catches skips, .only, deleted tests, removed assertions and exact checks swapped for toBeDefined().

It replaced my function with “rest unchanged”.

A change guard blocks placeholder edits and flags large, unexplained deletions.

Ten patches, and the same error every time.

Fix-thrash detection tells the agent to step back on the third identical failure, and to change approach or ask you on the fifth.

I have to wait for it to finish before I can correct it.

Type while it works. The agent reads your message at its next step and keeps going. Nothing you send is dropped.

A workspace for more than a single prompt.

OASIS combines a terminal-first coding agent with tools and a browser workspace that help you understand, change, and verify software.

Agentic coding loop

Inspect files, make a plan, apply focused edits, run approved commands, and summarize what changed across multi-step tasks.

Choose your model

Connect supported providers and compatible endpoints instead of being locked to one model vendor. Tool calling must be supported by your chosen model.

Extend with tools

Use Model Context Protocol (MCP), portable Agent Skills, hooks, custom commands, layered memory, bounded subagents, and a shared dependency-aware task board.

Terminal + browser

Work from the CLI or open the local browser dashboard for projects, tasks, notes, agent chat, visible tool activity, and approval prompts.

Review and recover

Use command approvals, file snapshots, checkpoints, rewind, saved sessions, and cost limits to keep multi-step work easier to review.

Build it into workflows

Use headless and JSON workflows, CI scripts, the GitHub Action, and the Node.js SDK for repeatable developer automation.

Flexible model connections.

OASIS does not bundle a model or provider subscription. During setup, choose a supported provider that matches your tools, budget, and preferred workflow. Small local models get a compact prompt, a 13-tool profile and tool-call repair.

Designed to be inspectable.

OASIS includes safeguards, but agent-driven code still needs human review. Understand what is enabled before using it on unfamiliar or important projects.

Current limitations

  • Shell commands normally run with your computer account permissions. The optional OS sandbox is disabled by default, currently targets Linux and macOS, and does not provide Windows isolation.
  • OASIS includes a VS Code-family integration and a plugin/marketplace adapter. Third-party compatibility is feature-by-feature, not a promise that every plugin works unchanged.
  • The browser dashboard keeps its projects, tasks, and notes separate from CLI workspace metadata. Its GitHub connection uses the GitHub CLI login on the host.
  • The browser PTY and process cleanup still need platform-by-platform validation. Android/Termux has not received real-device validation, and secure phone pairing is not implemented yet.
  • Desktop installers are unsigned. Clean-machine install, update, and uninstall journeys still need further release validation.
