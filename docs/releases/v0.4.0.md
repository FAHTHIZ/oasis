OASIS 0.4.0 is a substantial Beta update to the open-source coding agent and local-first developer workspace. It brings the CLI, browser workspace, integrations, agent runtime, and release tooling forward together.

## Highlights

- **Browser developer workspace:** a chat-first workspace with saved sessions, project context, Settings, and a utility rail for Terminal, Changes, and Tasks. Desktop and narrow-screen layouts have automated browser and accessibility coverage.
- **Coding-agent workflow:** multi-provider model support, scoped file operations, approvals, snapshots and rewind, task planning, diagnostics, verification, saved sessions, context controls, and optional isolated worktrees.
- **Integrations:** MCP tools, Agent Skills, hooks, plugins, bounded subagents, workflows, GitHub integration, a GitHub Action, and a VS Code-family extension.
- **Cost-aware model routing:** optional user-configured easy/strong model routing. Normal interactive prompts use conservative classification; benchmark runs can opt into explicit fixture-difficulty hints. Cost differences are estimates based on configured prices and observed tokens, not guaranteed savings.
- **Reliability and security hardening:** bounded process output, process-tree cancellation, safer session and backup storage, credential redaction, stronger network/URL checks, and clearer verification reporting.
- **Installer resilience:** the CLI installer can resolve the newest stable semantic-version Git tag if GitHub has no published Release object, and can use read-only Git tag transport when REST API requests are rate-limited. Installation still targets an exact commit SHA.
- **Verification repairs:** fixed token-estimation and pricing imports, removed duplicated evaluation code, restored `/audit`, `/add-dir`, and `/artifact`, and `/permissions` handlers, repaired Windows release resolution, and tightened test-server shutdown and CI concurrency checks.

- **Agent guardrails for common coding-agent failures:** change guard against `// ... rest unchanged` elisions, verification gate and claim check (pipe-masked exit codes don't count), test-weakening detection, commit secret scan, rule refresh after compaction, `/compact undo`, visible instruction truncation, retry guard, package vetting, and high-risk approval for process kills, desktop automation, container teardown and `kubectl` mutations.
- **Repository map:** `repo_map` tool and `/map` command give a ranked outline of files and top-level symbols; opt-in `repoMap` setting adds one to the first turn.
- **Web UI v3:** markdown replies, compact tool rows, live working-tree diff in the Changes panel (secret files hidden), keyboard shortcuts, sticky scrolling, and container-responsive layout. A recorded demo is in the README.
- **Browser tool fix:** navigations after the first page load were blocked; denied cross-origin navigations now keep the current page. Covered by a live Chrome E2E test.

## Published distribution assets

The GitHub release includes these downloadable desktop formats:

- **Windows:** x64 desktop installer (`.exe`)
- **macOS:** Apple Silicon / arm64 disk image (`.dmg`)
- **Linux:** x86_64 `.AppImage` and `.deb`
- **CLI:** Node.js 22 or newer; checksum-verified guided installation for supported terminal environments
- **Release metadata:** updater metadata files and a `SHA256SUMS` manifest

The published checksum manifest helps detect transfer corruption; it is not a digital signature or independent proof of publisher identity. Desktop installers are unsigned.

## Important Beta limitations

- OASIS is Beta software; this release does not claim full Claude Code parity or production security certification.
- Commands normally run with the current user's permissions. The optional OS sandbox is disabled by default, currently targets Linux and macOS, and is not full filesystem-read isolation. Windows OS isolation is not implemented.
- Desktop installers are unsigned. Publisher signing and automatic desktop updates are not configured.
- The browser workspace does not yet synchronize projects, tasks, and notes with the CLI workspace.
- Android has no native APK release. The optional native PTY path is not guaranteed on Android/Termux.
- The current evaluation suite is a regression harness, not a representative repository-scale head-to-head benchmark. No Claude Code parity, speed, accuracy, or token-savings claim is made.

Use a trusted project folder, back up important work, and review approval prompts before running commands or accepting changes.
## What this release does not establish

- The release does not certify OASIS as production-ready, stable, defect-free, or secure against arbitrary code execution.
- Passing packaging workflows does not prove clean-machine installation, first-run, update, or uninstall behavior on every advertised operating system.
- The `main` branch has continued to change since the immutable `v0.4.0` tag. Those later changes are not part of this release; current `main` has since advanced to package version `1.0.0` with Release Candidate 1 channel metadata.
- The next release uses a new immutable version/tag after its candidate commit and same-commit verification are complete. The current candidate is package version `1.0.0` with Release Candidate 1 metadata; do not replace or retag `v0.4.0` to absorb later development.
