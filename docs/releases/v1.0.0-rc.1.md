This is the first 1.0 release-candidate version on the development branch. It marks a transition from feature development into final product qualification. The 1.0 feature scope is established; the remaining work is concentrated on robustness, agent quality, reliability, accessibility, security-boundary validation, cross-platform behavior, and operational polish.

## Scope carried into the candidate

- Shared agent runtime across CLI, local browser workspace, desktop, editor, SDK, and GitHub Action surfaces.
- Multi-provider and local-model connection paths.
- Workspace tools, Git operations, approvals, command-risk checks, process management, and optional OS sandbox adapters.
- Sessions, project instructions, memory, compaction, checkpoints, rewind, and recovery records.
- Subagents, task coordination, workflows, MCP, hooks, Agent Skills, plugins, and extension import/export.
- Diagnostics, project checks, automatic testing, weakened-test detection, diff review, and completion-claim validation.

The [complete user guide](USER_GUIDE.md) and [architecture guide](ARCHITECTURE.md) document the current interfaces and subsystem boundaries.

## Qualification still required

This candidate is not the final stable 1.0.0 release. The release plan tracks these gates:

1. Fix the authenticated browser E2E task-completion/activity-fold lifecycle regression.
2. Resolve accessibility findings without weakening test coverage.
3. Pass all CI workflows on one immutable candidate commit.
4. Complete clean-machine install, first-run, update, and uninstall checks for Windows, macOS, and Linux.
5. Refresh the security-boundary review and document residual platform limits.
6. Align version, tag, release metadata, checksums, updater metadata, and published assets.
7. Decide and document the desktop-signing/provenance policy.

## Stable installation channel

The stable installer continues to resolve the latest stable versioned tag. It therefore installs the published `v0.4.0` release until a stable `v1.0.0` release is published. The `1.0.0-rc.1` package on `main` is available from source only.

## Important limitations carried forward

- Approved commands execute with the current OS user's permissions.
- Optional Linux/macOS sandboxing is disabled by default and is not full filesystem-read isolation; native Windows OS sandboxing is not implemented.
- Desktop installers from v0.4.0 are unsigned; clean-machine first-run/update/uninstall evidence remains open.
- Android has no native APK; Termux is not a fully qualified platform target.
- Browser Projects/Tasks/Notes data is not fully synchronized with CLI state.
- Runtime restarts do not resurrect live worker processes, PTY sessions, or pending approvals.
- The current 33-task evaluator is a regression/smoke suite, not a representative repository-scale coding benchmark.

Do not describe this candidate as stable, production-certified, or defect-free. Consult [the qualification plan](PROJECT_PLAN.md) for the latest same-commit evidence and acceptance status.
