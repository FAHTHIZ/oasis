Add CSV export and import to the taskflow project.

- New module `src/csv.mjs`:
  - `parseCsv(text)` returns the records as arrays of strings, following RFC 4180: fields separated by commas, records by LF or CRLF; a field in double quotes may contain commas, CR/LF and `""` for a quote; a final line break is optional; a UTF-8 BOM at the very start is ignored; a completely empty line is skipped. Errors use the 1-based physical line number where the problem starts: `CSV line <n>: unterminated quoted field` (counted from the line where the quoted field opens) and `CSV line <n>: unexpected quote` (a `"` inside an unquoted field, or any character other than a comma or line break right after a closing quote).
  - `exportCsv(tasks)` returns CSV text: the header `id,title,priority,status,due,tags,notes,created,completed`, then one record per task in the given order. Every record, including the last, ends with `\n`. `tags` are joined with `;`; `due` and `completed` are empty when missing. A field is wrapped in double quotes (with inner quotes doubled) when it contains a comma, a double quote, CR or LF, or starts or ends with a space. To prevent spreadsheet formula injection, a `title` or `notes` value that starts with `=`, `+`, `-` or `@` is written with a leading `'` (before any quoting).
- `store.importCsv(text)` adds the tasks in a CSV file and returns them:
  - The first record is the header. Columns may come in any order; only the export columns are allowed (`Unknown CSV column: <name>`), each at most once (`Duplicate CSV column: <name>`), and `title` is required (`Missing CSV column: title`).
  - Each later record becomes a new task with a new ID (continuing after the largest existing ID, in file order); the `id` column is ignored. `title`, `priority`, `tags` and `notes` are validated exactly like `store.add`. Empty `priority` means `normal`, empty `status` means `open`, and `tags` are split on `;` with empty items dropped. A `title` or `notes` value that starts with `'` followed by `=`, `+`, `-` or `@` has the `'` removed, so exports round-trip.
  - `due` must be empty or `YYYY-MM-DD` (relative values such as `today` are refused with the existing `Invalid due date: <value>` error). `status` must be `open` or `done` (`Unknown status: <value>`). `created` and `completed` must be empty or a timestamp `Date.parse` accepts (`Invalid timestamp: <value>`) and are stored as ISO strings; an empty `created` means now. A done task keeps its `completed` time, or now when it is empty; an open task never has `completed`.
  - A record with a different number of fields than the header fails with `expected <h> fields, found <n>`.
  - All or nothing: if any record is invalid, nothing is added or saved, and the error is `CSV row <n>: <message>`, where `<n>` counts data records from 1 (the header is not counted). An empty file, or a header with no records, imports nothing and is not an error (but header errors still apply when there is a header).
  - After saving, the store emits `added` for each imported task, in order.
- CLI: `taskflow export [--status open|done|all]` writes the CSV of the matching tasks in ID order to stdout, with no extra blank line at the end (default status: `all`). `taskflow import <file>` imports the file and prints `Imported <n> task(s).`. The usage line lists both new commands.

Keep every existing test passing and add tests for the new behavior.
