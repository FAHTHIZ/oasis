# Ship feature skill

1. Clarify acceptance criteria from the request and existing project conventions. Ask only if a missing fact changes the implementation materially.
2. Explore the relevant modules and tests before coding.
3. Implement the user-visible behavior, error states, input validation, and maintainable architecture—not just a demo screen.
4. Add or update tests and documentation as part of the feature.
5. Run focused checks, then the project quality gate. Inspect the diff and check for accidental secrets or generated clutter.
6. Do not deploy, publish a release, make irreversible remote changes, or claim test success without explicit evidence and necessary permission.
