Model provider

Connect runtime first

Choose a preset to fill in the endpoint, then confirm the exact model ID and test the connection. OmniRoute uses a local gateway on port 20128 and model auto; run oasis setup to install/start it or use this form when it is already running. Some OmniRoute setups require the local endpoint key shown in its dashboard. OpenRouter requires a model ID from its catalog; Ollama requires a running local server and an installed model. Keys entered in the desktop app use the operating-system secure store. The CLI/browser setup path stores keys in the local OASIS config file with restrictive permissions, so use it only on a trusted computer. Provider credentials are accepted only from this same device over localhost. If you connect from a second device over the private-Wi-Fi bridge, configure the provider in the host terminal instead—this HTTP connection is not encrypted.

Choose a provider to see its official key page. Desktop mode uses OS-backed encrypted storage. CLI/browser mode stores the key in your local OASIS config with restrictive permissions, not OS encryption.

      Advanced · local connection and privacy
      
OASIS connects to a runtime on this computer by default. It is not open to the public internet by default. Remote access requires explicit server options. Never share your runtime connection token. Browser connections use a one-time token kept in this tab's session storage.

Configure stdio MCP servers for the next coding session.

    
Adding an MCP server permits Oasis to launch the configured executable in your workspace when a new session starts. Use trusted commands only. API tokens should be provided through named environment variables, never placed in arguments. Save changes explicitly; this panel does not launch servers immediately.
