# Changelog

This file records notable user-facing product changes. It does not imply that an entry has been published as a GitHub Release.

## Unreleased

Changes after 1.1.0. Entries include feature work, reliability improvements, and security hardening; benchmark-driven fixes and their regression evidence are documented alongside the relevant changes.

- **MCP client is the official SDK.** The hand-written stdio, Streamable HTTP and SSE clients and the hand-written OAuth (discovery, registration, PKCE, token exchange, refresh) are replaced by `@modelcontextprotocol/client` 2.4.0 (Apache-2.0), which Claude Code, Gemini CLI and Cline also build on. On the [official MCP conformance suite](https://github.com/modelcontextprotocol/conformance) (21 client scenarios, spec 2025-11-25) the old client passed 2 of the 4 non-auth scenarios and almost no auth scenarios; the new one passes all 21 with no warnings. New behaviour that came with it: scope step-up on `insufficient_scope`, `client_secret_basic`, path-based authorization-server discovery, resource-identifier normalisation, SEP-1034 elicitation defaults, SSE retry, and opt-in Client ID Metadata Documents (`oauth.clientMetadataUrl`). OASIS keeps its own guards on top: the HTTPS-only/pinned-DNS OAuth fetch (new opt-in `OASIS_MCP_OAUTH_ALLOW_LOOPBACK=1` for a local authorization server), the 4 MiB response cap, process-group stdio servers with a filtered environment, and tool pinning. Servers must now send `serverInfo` in `initialize`, and authorization metadata must list `response_types_supported`, as the spec requires. Non-blocking MCP startup now begins once the session exists, so loading the SDK adds nothing to session start. Run `scripts/mcp-conformance/run.sh` to repeat the measurement.
- **Shell commands are parsed with the tree-sitter bash grammar.** The hand-written splitter is replaced by `@vscode/tree-sitter-wasm` (MIT, the grammar build VS Code ships; no native build), as in Claude Code, Codex, Gemini CLI and OpenCode. The legacy splitter returned no risk for `$'\x72\x6d' -rf ~`, `bash <<< "rm -rf ~"`, `f(){ rm -rf ~; }; f`, `case x in x) rm -rf ~;; esac` and `for d in ~; do rm -rf "$d"; done`; all are now refused. Comments are no longer read as commands, run-time computed programs and `eval` of computed text need a person, and lines the grammar cannot parse always ask. Deny and ask permission rules match commands inside functions, case arms, here-strings and variable indirection (`Bash(git push:*)` now catches `f(){ git push; }; f`); allow rules stay strict. PowerShell and cmd lines keep their own splitter. Tests in `test/shell-ast.test.mjs`.
- **Repo map definitions come from tree-sitter.** For JavaScript, TypeScript/TSX, Python, Go, Rust, Java, C#, C/C++, Ruby, PHP and shell; other languages keep the line patterns. Against compiler ground truth (Python `ast` on requests, flask and httpx: 2,793 definitions; the TypeScript compiler API on ky and zod: 3,082), definition F1 rose from 87.0 to 100 for Python and from 86.4 to 96.7 for TypeScript. Local helper functions are left out, and words in comments and strings no longer count as symbol uses. Scans are cached on disk per file by mtime and size, so a new session maps OASIS (836 files) in ~0.3 s; the first-ever scan takes ~3.9 s (the old regex scan took ~0.76 s every session). `OASIS_REPO_MAP_CACHE=0` and `OASIS_REPO_MAP_PARSER=regex` turn these off. Tests in `test/code-ast.test.mjs`.
- Bench gateway: the log line is written before the reply ends, fixing an intermittent CI failure.
- Providers: an error that states a short wait outright ("Retry after 43s", 90 s or less, no daily/monthly/credit wording) is waited out on HTTP 429 or 402 instead of ending the run. Seen live on 2026-11-06: Pollinations' keyless endpoint answers its per-IP rate window with HTTP 402, which OASIS reported as a billing error and failed `taskflow-search` before the model had done anything. Real billing 402s still fail fast. Test in `test/explicit-short-wait.test.mjs`.
- Bench gateway: request spacing counts from the end of the previous reply, which is how Pollinations measures its window.
- **Leaner command and edit results for the model.** `run_command` and `run_shell` results no longer repeat `approved: true`, `signal: null`, an empty `stderr` and the false `stdoutTruncated`/`stderrTruncated`/`timedOut`/`cancelled` flags on every call; set flags are still shown. The "no language server found, install one with ..." notice is given in full once per session, and later write/edit results just say `unavailable`. Only the text sent to the model changes: the result object that the verification gate, claim check and traces read keeps every field. Token benchmark: taskflow-search ~157,006 → ~156,904, normalize-token-usage ~262,528 → ~261,672 (cache-weighted ~45,074 → ~44,816).
- **Prompt caching holds across wide parallel steps, and OpenAI Chat Completions requests carry a cache key.** Anthropic only looks back 20 content blocks from a cache breakpoint for a cached prefix. OASIS marked just the system prompt, the last tool and the newest message, so a step with ten or more parallel tool calls (each adding a `tool_use` and a `tool_result` block) moved the breakpoint out of reach and the next request re-sent the whole history at the uncached price. The user message where the previous request ended now gets a breakpoint too (4 in total, Anthropic's limit). Chat Completions requests to api.openai.com now send the same per-session `prompt_cache_key` as Responses requests (other gateways: `OASIS_PROMPT_CACHE_KEY=1`), so a session's requests go to the same cache.
- **Subagent usage is counted and shown per agent.** Background subagents (`run_in_background`, auto-dispatched workers) reported no usage at all: their requests never reached `/cost`, the web usage panel or the headless `usage`/`total_cost_usd`, even though they were billed. A failed or cancelled subagent also lost the tokens it had spent before failing. Each agent record now keeps `usage` (requests, input, output, cache-read tokens, cost), shown by `agent_status` and `/tasks`, returned in the `task` result and saved with the session. Foreground subagent usage events carry `agentId` and `agentType` next to `subagent`; background ones go to the session's `onBackgroundUsage` sink, which the CLI, headless mode and the web UI now set, so they count even after the turn that started them has ended. Covered by `test/subagent-usage.test.mjs`.
- Eval: each OASIS trial now records a compact tool trace (tool, the path/command/pattern it acted on, result size, failed flag; secrets redacted, no file contents, at most 200 steps) and the input/output tokens of every request, so a failed or expensive live run can be diagnosed from the committed report. Test in `test/eval.test.mjs`. `scripts/bench-gateway.mjs` is the logging gateway used for live same-model runs (forced model, request spacing, usage log); see `docs/BENCHMARKS.md`.
- **Smaller fixed prompt on every request.** The system prompt and tool schemas are resent on every step and were two thirds of the token benchmark's input. Tool descriptions are tighter (safety behaviour such as `delete_file` approval is still stated), rarely used tools (`command_output`, `kill_command`, `memory_save`, `memory_search`, `delete_file`) are listed in the prompt and loaded with `tool_search` on first use instead of being sent each time, and the memory, delegation and skill sections are shorter. The prefix stays byte-stable across steps. Token benchmark: taskflow-search ~179,776 → ~157,006 input tokens (−12.7%; cache-weighted −11.2%), normalize-token-usage ~285,296 → ~262,528 (−8.0%; cache-weighted −7.0%). `apply_patch` deletes still work with `delete_file` deferred.
- **Superseded tool results go first when the context fills up.** Before compaction summarises history or old tool output is pruned, results that a newer result in the conversation fully covers are replaced by one-line stubs: an older read of a file that was read again (same or wider range), an earlier run of the same command (the stub keeps the exit code and the last 300 characters), an earlier `git_status`/`git_diff` with the same arguments. If that alone brings history under the threshold, no summary request is made. It is deliberately not applied on every step: rewriting an old message breaks the provider's prefix cache, and on the token benchmark doing it eagerly cost 12% more cache-weighted input on `taskflow-search` for a 0.4% raw saving. `OASIS_SUPERSEDE_RESULTS=0` or `"supersedeResults": false` turns it off.
- **OpenAI `apply_patch` patches work.** GPT-5.x and Codex models are trained to edit files with the V4A `*** Begin Patch` format ([GPT-5.1 prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/gpt-5-1_prompting_guide)); in OASIS such a call failed with "There is no tool named apply_patch" (or, through the shell, "command not found"), costing a step and pushing the model off its trained editing path. OASIS now accepts an `apply_patch` call with JSON or freeform arguments and a shell call running `apply_patch <<'EOF'`. The new `src/apply-patch.mjs` ports OpenAI's reference parser (anchors, whitespace fuzz, `*** End of File`, Add/Delete/Move) and computes every file first, so one bad hunk changes nothing; the agent then applies each file as a normal `write_file` / `delete_file` call, keeping plan mode, permission rules, hooks, approvals, protected paths, snapshots and file locks. The tool is not in the default schema (token benchmark unchanged: taskflow-search ~179,774 vs ~179,776 input tokens); it is declared after first use so history stays valid. A declined approval (for example a deletion) stops the patch and is reported with what was and was not applied, never as success. Covered by `test/apply-patch.test.mjs` (parser, recognition, end-to-end add/update/delete/move, declined approval, plan mode, secrets and workspace escape).
- **Leaner git results for the model.** `git_status` and `git_diff` results reached the model with the full git command line (800 characters of secret-path excludes for a diff) and `output`, a second copy of stdout, so a 3,500-character diff took 7,900 characters of history on every later request. The model now gets stdout once, stderr and flags only when set, and the command only when git failed; the in-process result is unchanged.
- **Security: attack-tested enforcement fixes (2026-11-06).** Each was reproduced with a failing test first; details in `docs/SECURITY_RELIABILITY_AUDIT.md`.
  - The protected-config guard resolves symlinked folders and canonical roots: `write_file cfg/settings.json` through a `cfg -> .oasis` symlink, or the real path of a workspace opened through a symlink, wrote settings and git hooks with no warning under `--yes` or an allow rule. `generate_image` and `text_to_speech` get the same check.
  - No-prompt read-only commands expand unquoted globs against the workspace and ask only when a match is a secret file or leaves the workspace (`cat .en?` read `.env`; `ls src/*.js` still runs) and before recursive searches that would read a secret file (`grep -r KEY .`, `rg --hidden`, `diff -r`, `git grep --untracked`) or follow a symlink out; `git show HEAD:.env` asks too.
  - Read-only git asks when the repository's own config names a diff, textconv, filter or gpg program; `git_status`/`git_diff` switch repository filters off. These ran without a prompt.
  - Deny/ask rules also match `$'git' push`, `{ git push; }`, `(git push)`, `if`/`while`/`for` bodies, `exec -a`, `env -S` and `find -exec`.
  - `read_mcp_resource` results go through the untrusted-content guard, and one zero-width character inside a word no longer hides an injection phrase.
  - Secret-shield placeholders stay as placeholders in `fetch_url`, `web_search` and `browser` arguments, so an injected page cannot get a real key sent in a URL, and in `task`/teammate prompts, so a subagent no longer sends the real key to the provider; subagents share the parent's vault for their own edits.
  - Debug logs, trajectory exports, session previews, memories, artifacts, approval text and telemetry tool details now redact every credential format the secret shield knows (Stripe, Groq, Hugging Face, GitLab, npm, xAI, AWS, JWTs, private keys, URL passwords, `.env` assignments); the debug log used to write tool arguments with real values.
  - Extra folders (`--add-dir`, `/add-dir`, `permissions.additionalDirectories`) refuse credential folders such as `~/.aws`, and their `.git/hooks`, `.git/config`, `.mcp.json` and settings get the protected-config prompt.
  - `scripts/bench-gateway.mjs` refuses browser (`Origin`) and DNS-rebinding requests and redacts keys echoed in logged upstream errors.
  - `oasis mcp serve --allow-edits` refuses edits to protected config (git hooks and config, Oasis/Claude settings, `.mcp.json`, editor task files); it used to write `.git/hooks/pre-commit` for any client.
  - Read-only git also checks checked-out submodules' own configs for filter, diff and gpg programs; `git status` used to run a submodule's clean filter with no prompt.
  - Google service-account key files (`service-account*.json`) and Terraform state (`terraform.tfstate`, `.backup`) are treated as secret files.
  - Stdio MCP servers get the same credential-free environment as commands and hooks (`DATABASE_URL`, `MYSQL_PWD` and others used to pass); use `passEnv` or `env` to give a server one.
  - Shell writes into `.git/hooks`, `.git/config` and other protected config are caught without a space after `>`, after `cd .git/hooks`, through split quotes, and from `sponge` or Python `open(...)`.
  - Commands, hooks and eval agents share one credential-name list; `DATABASE_URL`, `*_PWD`, `*_PASSPHRASE`, `*_AUTH`, `*_DSN`, `*_WEBHOOK_URL` and `*_PAT` are removed too.
- **`write_file` keeps a file's line endings and byte-order mark.** Rewriting an existing file whose newlines were all CRLF (common in Windows repositories) wrote the model's LF text, so Git showed every line as changed; a leading BOM was dropped too. Consistent CRLF endings and a BOM are now carried over (the result lists them under `kept`); mixed-ending files, LF files, new files and content that already uses CRLF are written as given. `edit_file` already preserved both. Covered by `test/edit-match.test.mjs`.
- **Token-efficiency benchmark.** `node bench/tokens/run.mjs` drives the real agent loop with a scripted provider through a fixed 17-call sequence on `taskflow-search` and records what each request carries (system prompt, tool schemas, tool results, history), how much of it a prefix cache could reuse, and whether reported usage adds up. Baseline at `cf469f6`: 18 requests, ~180,898 input tokens, two thirds of it the system prompt and tool schemas resent every step. `--check` runs in `npm run check`.
- **Headless setup errors honor `--output-format`.** When `oasis -p` / `oasis exec` failed before the run started (no provider configured, usage errors), the message was printed as plain text on stdout, so `--output-format json` and `stream-json` consumers received unparsable output and text-mode redirects captured the error as the answer. JSON modes now write one `{"type":"result","is_error":true,"subtype":"error_during_execution"}` object to stdout; the human message always goes to stderr; the exit code stays 1. Uncaught CLI errors also go to stderr. Covered by `test/headless-setup-errors.test.mjs`.
- **Agent-loop reliability fixes (2026-11-06).** Found with scripted-provider regression tests:
  - Sessions longer than the 120-message save cap (one 60-step turn is enough) could no longer be saved: the plain tail slice dropped the system message, so every mid-turn and end-of-turn save failed with "Session history must begin with system context" and a crash lost the turn. The saved tail now keeps the system message, starts at a complete exchange, and keeps the user request it belongs to.
  - Provider retries: the response-header timeout was armed once for the whole retry sequence, so a few patient 5xx retries (or Retry-After waits) tripped it and a provider that answered every attempt was reported as "timed out". Retry waits now pause the timeout and each attempt gets its own. Retry-After was also capped at 5 s, so a 429 saying "retry in 30 s" was retried early and failed again; it is now honoured up to 60 s, and longer ones are not retried inline (the rate-limit wait, fallback chain or error takes over).
  - No-progress cycles: the repeated-call guard only caught the same call three times in a row, so a model alternating between two reads (A, B, A, B) or re-issuing the same batch each step ran to the 60-step limit. A call with the same inputs and result seen in 3 of the last 8 steps with no file edit in between now gets a warning, and at 4 the turn stops with a clear "stuck" message.
  - Empty replies: a reply with no text and no tool call (for example after a tool result) ended the turn as finished with a blank answer, and the empty message stayed in context. It is now dropped and the model is asked again (twice); if it stays empty, the turn ends with a clear notice and `emptyReply: true`.
  - Parallel subagents editing the same file: two concurrent `edit_file` calls both read the original, so the later write silently dropped the earlier edit while both reported success. `edit_file`, `write_file`, `multi_edit`, `notebook_edit` and `delete_file` now run one at a time per path.
  - Mid-stream disconnects: a chat-completions stream that closed with neither `finish_reason` nor `[DONE]`, or an Anthropic stream with no `message_delta` stop reason or `message_stop`, was accepted as complete, so a cut-off half sentence became the final answer. Both now count as an interrupted stream and are restarted.
  - Claim check: a test run that timed out or was stopped (no exit code) left the claim check with nothing to contradict, so "all tests pass" after a hung `npm test` went through. Such a run now counts as unfinished and the claim is sent back to reconcile; timed-out `run_shell` checks are recorded too.
  - Resume repair: interrupted-history repair filled in missing tool results but left tool results that answer no directly preceding call (late results, duplicates, remains of a trimmed exchange), which OpenAI chat, Responses and Anthropic all reject with a 400 on every later request. They are now dropped. The filler results also carried an internal `result` field that was sent to the provider; they now carry only wire fields.
  - Anthropic whitespace text: an empty assistant reply was replayed as a single space and empty user text as an empty block, which Anthropic rejects ("text content blocks must contain non-whitespace text"); because history is replayed, every later request in the session then failed. Whitespace-only text is now replaced with a short placeholder or dropped from block lists.
  - Step-limit summary: the final no-tools summary request made when a turn hits its step limit did not get the turn's abort signal, so cancelling at that point left it running until the provider timeout (minutes). It now gets the signal (and the retry/rate-limit callbacks), cancellation propagates as an abort, and an empty summary falls back to the step-limit notice instead of a blank answer.
  - SDK `query()`: a consumer that stopped iterating early (`break`, `return`, a thrown error) left the agent running in the background, still calling the model and running tools with nobody reading its events. The generator now owns an abort controller (linked to `options.abortController`) and aborts the run when iteration stops early.
  - Open checklist at "done": a final answer while the checklist written this turn still had pending or in-progress steps ended the turn as complete. It is now sent back once to finish those steps or update the checklist and say what is unfinished. A checklist left open by an earlier turn does not trigger it.
  - `oasis -p` and `oasis eval` sent whole-reply requests, so a provider that stalled could hold a run for the 600 s request timeout (live, a Pollinations stall cost 300 s; in a direct comparison, 2 of 3 whole-reply requests to Pollinations hung past 150 s while 3 of 3 streamed ones answered in under 6 s). They now stream without printing partial text, like the interactive terminal, so the 120 s header timeout and the idle watchdog apply. `OASIS_NO_STREAM=1` opts out.
  - Checkpoints under parallel subagents: subagents share the parent's checkpoint store, and two overlapping captures of the same file both passed the "already captured" check. The second snapshot replaced the first, and could be taken after the first agent's write, so `/rewind` restored the edited text instead of the original. Bytes were also counted twice, so the checkpoint budget filled early. The capture now checks again after its reads and keeps the first snapshot.
  - Empty replies stopped by the provider (chat `finish_reason` `content_filter`/`error`, Anthropic `stop_reason` `refusal`) are reported with the finish reason instead of re-asked, since a re-ask returns the same. Re-asks are billed and counted like any other request; a cancel during a long Retry-After wait stops at once (both covered by tests).
  - Fallback chain and dropped streams: a stream that kept closing before the reply finished, after its in-place restarts, ended the turn with an error instead of moving to the next model in `fallbackModel` (only "stream stalled" did). Such drops now count as a server failure for the chain; malformed tool calls still go to the turn loop's corrective retry.
  - Tool arguments sent as the text `null` (some models do this for tools with no parameters) were rejected with "must be a JSON object, not object". They now read as no arguments; other non-object values are named plainly ("not a number").
- **Fixes from live head-to-head runs (2026-11-05).** Found by running OASIS, Aider and OpenCode on free gpt-oss-20b and Nemotron 3 Ultra endpoints:
  - gpt-oss tool names leaking harmony tokens (`edit_file<|channel|>commentary`, `functions.read_file`) are cleaned before dispatch. One such name made the gateway reject the whole request with HTTP 400.
  - A streamed tool-call fragment that arrives at a new index with no id or name (one gateway sent call 0's closing `}` as index 1) now continues the previous call instead of becoming a broken, nameless one. OpenCode crashed on the same stream with "Expected 'id' to be a string".
  - `run_command` accepts `args` sent as one string.
  - `glob_files` accepts a `path` folder, as Claude Code's Glob does; it used to be ignored, so `{path: "src", pattern: "*.mjs"}` searched the root, found nothing, and the model decided the project had no modules. A root-only pattern with no matches now lists matching files in subfolders.
  - Singular/plural slips in tool names (`search_file`) map to the one matching tool instead of costing a turn.
  - `oasis eval` records the source revision loaded at start and flags runs where HEAD moved; a long run had been credited to a fix committed after it started.
  - The verification gate no longer asks for a separate diff review after a passing check for targeted edits, so a finished turn no longer produces a second, contradictory final answer. Files the agent created are exempt; existing files it rewrote wholesale still need a diff review. When new code has no test change, the gate asks the model to call the new module directly with edge cases.
  - Waits after the first rate-limit wait in a turn count down in the status line.
  - Smaller requests: the README in context is clipped to 2.5k characters, skill catalogue lines to 160, and the `task`, `run_command`, `run_shell`, `fetch_url` and `ask_user_question` schemas are shorter (about 1.6k fewer characters per request).
  - `npm run bench:live` with `--router` writes an OpenCode provider config, and the eval runs external agents with `PWD` set to the task workspace. OpenCode used the inherited `PWD` and edited the wrong folder, which made the first published OpenCode 0/3 invalid.
  - A 400 caused by the model's own harmony output ("Unknown role: assistant<|channel|>commentary", seen from a gpt-oss gateway after 258k tokens of a passing run) is retried up to twice instead of ending the turn. The app retries it too.
  - Headless turns (`oasis exec`, evals) no longer send `ask_user_question`, which could only answer that no one is there, and `exit_plan_mode` is sent only in plan mode. The system prompt drops the `git_status` reminder outside a git repository. In an empty repository, the first request is about 6.3k tokens headless (Qwen3 tokenizer).
  - The small-context profile is 12 tools; the docs said 13 (`search_files` was listed but never sent).
  - The verification gate names what is missing: the files whose diff was not reviewed and the exact check to rerun when a later edit made it stale (in a live gpt-oss run the model reported a pass from before its last edit). The terminal and web UI show "Not finished yet: …" when the gate sends the model back, and a turn that answered with the gate still open ends "Done" under its "Not fully checked" line instead of "Paused".
  - The README has an unscripted terminal recording with gpt-oss-20b next to the scripted one, with the model's slips noted.
  - Built-in skills are listed without a `[built-in]` tag on every line; `Skill(...)` deny rules still match.
  - The app retries a failed update check after a few seconds instead of 30 minutes. Two app end-to-end tests were flaky because their "not busy" check read the wrong element.
  - Windows CI runs `install.ps1` against fake `node`, `npm` and `winget` to check PATH handling and safe failures without touching the machine-wide PATH.
- **Terminal polish from live runs.** Parallel lookups fold into one line ("Read 2 files, searched 1 pattern" with the targets below), as in Claude Code and Codex; a failed lookup keeps its own line. File errors read "Not found: src/x.mjs" instead of Node's errno text. Code blocks no longer print a language label that looked like part of the command. Edit summaries say "1 addition" instead of "1 addition and 0 removals". Retry notices name server errors with their status, and the "tokens sent" estimate counts tool schemas.
- **Reasoning stays out of the answer.** Streamed `reasoning_content` (DeepSeek, vLLM), `reasoning` (gateways) and Gemini thought chunks are kept apart from the reply, and DeepSeek and Kimi get their reasoning replayed on later requests, which their APIs require when tools are used (they return 400 otherwise).
- **Test gate fix.** A test added to a root-level `test.mjs`, `tests.py` or `spec.js` now counts as a test change, so "add a test" requests are no longer reported as unchecked.
- "Add to Cursor" and "Install in VS Code" button links (cursor://, cursor.com/install-mcp, vscode:mcp/install, vscode.dev/redirect/mcp/install) install the MCP server they describe.
- Whatever you add from a chat works in that chat: MCP servers (also a plugin's bundled ones) start right away, new skills load with `load_skill` at once. Fixed: servers added from a chat were only read from the older `mcp-servers.json`, so they waited for the next session.
- Add-ons that need a key say which one after installing; paste it in the chat and the agent saves it for that MCP server or plugin (one confirmation, no reinstall, running servers restart).
- Gemini CLI extensions, Codex plugins and marketplaces, and Agent Plugins packages install with `oasis add` / `/add` / "install this": they are converted to Claude Code plugins (TOML commands, GEMINI.md, settings, hooks and MCP servers included), and Gemini extensions use their platform release build when one exists. Tested on gemini-cli-extensions/security and openai/plugins.
- `oasis add`, `/add` and the agent understand install commands copied from READMEs (`npx`/`uvx`/`docker` lines, `claude|codex|gemini mcp add …`, `/plugin install …`, `npx skills add …`) and skills.sh, npm, PyPI, Smithery and raw GitHub links.
- First start tells people coming from Codex, Cursor, Gemini CLI, Hermes, OpenCode, Windsurf, Cline or Antigravity what `/import` would bring over (shown once per set of items).
- Project memory now belongs to the repository: every subfolder and git worktree of a repo shares one memory, as in Claude Code. Memory saved under the old per-folder key is still used.
- **Add anything: `oasis add`, `/add` and "install this".** Paste a GitHub link, `owner/repo[#name]`, `plugin@marketplace`, an MCP server URL, an npm MCP package or an MCP Registry name. OASIS detects what it is (a Claude Code marketplace or plugin, a native OASIS package, Agent Skills, an MCP server or a folder of servers, or Markdown agents), shows one summary, and installs and configures it. In chat the new `add_extension` tool does the same after one approval, and starts new MCP servers in the same chat. Tested live against obra/superpowers, wshobson/agents, anthropics/skills, microsoft/playwright-mcp, modelcontextprotocol/servers, Context7 and the GitHub MCP server.
- **Leaner, sharper agent loop.** The first request to the model is about 60% smaller (about 7.1k tokens, down from 17.6k): 23 core tools go out up front, and the other tools load the first time they are needed, by search or by calling them directly. Subagents can reach them too. The system prompt is now a short core covering how to work, honesty and safety, and notes for rarer tools arrive with the tool. Skill catalogue lines are capped at 200 characters, and skills marked `disable-model-invocation: true` stay out of it. Saying "ultracode" loads the workflow tool. Measurements: `docs/BENCHMARKS.md`.
- **Read-only commands run without asking.** `ls`, `cat`, `grep`, `rg`, `find`, `git status`, `git diff`, `git log`, `--version` and similar commands, inside the project, now run straight away, as in Claude Code. A command still asks when it touches a path outside the project or a secret file, or when it uses redirects, substitution, `sudo`/`xargs`/`env` prefixes or interactive mode. Turn this off with `OASIS_READ_ONLY_COMMANDS=0` or `permissions.readOnlyCommands: false`.
- **Shell on by default for the agent.** `run_shell` (pipes, `&&`, redirects) is now on by default on macOS and Linux, as in Claude Code and Codex. Every line is still split into its simple commands for blocking, risk checks and approval. Turn it off with `shell.enabled: false` or `OASIS_SHELL=0`. Windows keeps the PowerShell tool. The app's own terminal box still takes shell syntax only if you turned shell on yourself.
- **Project discovery at start.** The environment block now names the project's languages and manifests, its package manager and key scripts, the test command, whether dependencies are installed, and any toolchain the project needs that is not on PATH. This saves the model several exploratory calls on every task.

If a resumed worker fails, its worktree is kept for review instead of being deleted. Saved sessions also no longer lose a worktree agent's branch, path and commit when they are loaded.
- **Fewer false alarms from the untrusted-content guard.** Pages that say "You are now logged in" and API docs that say "send the access token in the Authorization header" are no longer flagged (a flag holds risky actions for the turn). Role rewrites ("You are now DAN…") and secrets sent to an outside address are still caught, and sending a `.env` file to an address is now detected too.
- **MCP sign-in resists mix-up attacks.** OAuth sign-in checks the RFC 9207 `iss` parameter against the discovered authorization server and refuses a response from a different server, or one with no issuer when the server promised to send it.
- **`oasis doctor` suggests the sandbox.** When the OS sandbox is available but off, doctor says how to turn it on (`/sandbox on` or `"sandbox": {"enabled": true}`).
- **Desktop app security updates.** Electron 45.1.0 → 45.2.1 (Chromium security fixes in the shipped app) and electron-builder 26.4.0 → 26.18.0, which removes the critical `tar` and the high-severity advisories in the installer toolchain. Production dependencies have no known advisories.
- **Auto mode can't be steered by relayed messages.** Messages from other sessions, background-event prompts and hook notes are no longer counted as your intent by the auto-mode classifier.
- **Head-to-head evals against Codex and Gemini CLI.** `oasis eval --codex` and `oasis eval --gemini-cli` run those agents headless on the same disposable task copies and hidden verifiers as `--claude-code`, record tokens from their JSON output, and produce reports that `--compare` accepts.
- **Better OpenAI prompt-cache hits.** Responses API requests to api.openai.com carry a `prompt_cache_key` (a hash of the session ID, separate per subagent), which keeps a long conversation on the same cache, as Codex does. Cheaper and faster turns. `OASIS_PROMPT_CACHE_KEY=1` sends it to other Responses endpoints, `=0` turns it off.
- **Subagents survive restarts.** Shared-workspace subagent conversations are saved next to the session, so after a restart or `--resume`, `send_message` resumes the worker with its full context instead of failing with "no live worker". Workers interrupted mid-task are resumed with a note to re-check the files first. Saved transcripts are validated on load (no injected system messages, matching agent ID) and removed with the session.

- **Parallel tool calls.** Requests now let the model ask for several tool calls at once (`parallel_tool_calls` was hard-coded to false, although the executor already ran read-only batches concurrently). Exploring a codebase takes fewer model round trips. `parallelToolCalls: false` or `OASIS_PARALLEL_TOOL_CALLS=0` restores one call per response.
- **Crash-safe settings and state.** The main config, MCP server config, saved credentials, input history, plugin state, workflow state and backup manifests are written atomically, so a crash or full disk mid-save can't leave a truncated file.
- **Sandbox that doesn't break builds.** Existing package-manager caches (`~/.npm`, pip, uv, cargo, Go modules, Maven, Gradle, pnpm, Bun, Playwright and others) are writable inside the OS sandbox, so `npm install`, `cargo build` and `go test` work with the sandbox on. ## 1.0.0 — stable (prepared November 1, 2026; released November 4, 2026)

First stable release, prepared on `main`; the `v1.0.0` tag and GitHub Release have not been created yet. Release notes: [docs/releases/v1.0.0.md](docs/releases/v1.0.0.md). Installers are unsigned and ship with `SHA256SUMS`.

Reliability and token-efficiency work driven by common coding-agent complaints:

- **No unrequested commits or pushes** — `git_commit`, `git_push`, `create_pull_request`, and shell `git commit` / `git push` / `git remote add|set-url` / `git config --global` / `gh pr create` run only when the current request asks for that ("commit", "push", "open a PR", and so on). Otherwise the model is told to leave version control to the user. Found in a live 3B run that committed, set a global git identity, added a remote and pushed. Opt out with `allowUnrequestedGitWrites: true` or `OASIS_ALLOW_UNREQUESTED_GIT_WRITES=1`.
- **Eval runs cannot publish** — the agent under `oasis eval` now gets a credential-free environment, and git pushes from the disposable workspace are rewritten to an unreachable URL.
- **Assisted verification for small models** — on local servers or windows of 32K or less, when the model edits files and then stops without checking its work, OASIS runs the review itself: `git_diff` (or reads the changed files outside Git) plus the detected project test, or `node --check` / `python3 -m py_compile` when there are no tests. Results go back to the model (at most twice per turn). Force with `assistedVerification: true` or `OASIS_ASSISTED_VERIFICATION=1`; `0` turns it off.
- **Give-up and false-claim nudges** — a model that quits after one error, or says it created or changed a file it never touched, is told so and asked to continue. On small or local models, a false claim or a canned refusal ("I'm sorry, but I can't assist with that") is removed from the conversation before the retry, because small models otherwise repeat it, and the reminder names the file from the request.
- **Code-block fallback for weak models** — if a small or local model still pastes the new file as a fenced code block instead of calling `write_file` after a nudge, OASIS writes that block to the new file the request names (new files only, through the normal tool path and permissions, never pseudo-code that "calls" agent tools), then runs the usual checks. Aider-style whole-file editing, limited to the case where it is safe.
- **More small-model fixes from a live 3B run** — several JSON call objects in one code fence are all recovered; the code-block fallback never writes tool-call JSON into a file; after a failed check, a corrected whole file pasted as a code block replaces the file the model created in that turn (twice at most, full replacements only); `tool_search` now says it finds tools, not code, so models stop looping on it.
- **Made-up tool names get an answer** — a reply that only "calls" tools that do not exist (`{"name": "git_init", ...}`) is no longer taken as the final answer; the model is told nothing ran and given the real tool list (at most twice).
- **Sturdier fenced tool calls** — fenced call blocks now get the same JSON repairs as native arguments (raw newlines inside strings, a stray closing brace), so a small model's `write_file` with a multi-line file body runs. If a call still cannot be read, it and the calls after it are skipped (they usually depend on it) and the model is told which call to resend, instead of running a later `run_command` against a file that was never written.
- **`--debug raw`** — logs each model reply before tool-call recovery and cleanup, for diagnosing local model output formats.
- **Echoed tool results stripped** — small models that reproduce `<tool_response>` blocks in their reply have them removed before history, with a reminder not to.
- **`git_diff` shows new files** — untracked files now appear as new-file diffs (secret-looking paths such as `.env` and keys are skipped), with an `untracked` list. It also works in a freshly initialized repository with no commits (previously `git diff HEAD` failed there, so the first change could never be reviewed).
- **Leaner tool results in small windows** — at 32K or less, non-blocking notes such as "LSP unavailable" are dropped from tool output.
- **Act, don't describe** — when a change request gets a tutorial-style reply with no tool use, or the model announces a next step ("I need to create the file") and stops with nothing changed, OASIS nudges it to do the work (at most twice per turn). Found by running a real 1.5B local model end to end.
- **More text tool-call formats** — bare call objects followed by commentary, and XML-attribute calls (`<function name="..." arguments='{...}'>`) inside `<tools>` wrappers, are recovered.
- **Near-greedy sampling for local servers** — local model endpoints default to temperature 0.2 (llama-server and Ollama default to about 0.8, which makes small models drift between call formats). Set `temperature` in the provider config or `OASIS_TEMPERATURE` to override; hosted APIs keep their defaults.
- **UTF-8 PowerShell writes** — the PowerShell tool defaults `Out-File` (and `>`), `Set-Content`, `Add-Content` and `Export-Csv` to UTF-8, so Windows PowerShell 5.1 no longer writes UTF-16 or ANSI and corrupts non-English text.
- **Security hardening** — the bubblewrap sandbox no longer re-exposes `/tmp` socket directories (such as ssh-agent) or whole `/tmp` entries, only toolchain prefixes. Tool-call recovery from reply text ignores quoted and example calls.
- **Compact system prompt for small windows** — at 16K tokens or less the system prompt shrinks from ~4.2K to ~1.6K tokens while keeping the core correctness and safety rules; with the small tool set, an 8K window keeps ~4.3K tokens for work instead of ~1.7K.
- **Context windows from the provider** — unknown hosted or self-hosted models read their window from `GET /models` (DeepSeek, OpenRouter, vLLM) instead of assuming 32K; DeepSeek V4 (`deepseek-v4-pro`, `deepseek-flash`) is listed at 1M. `OASIS_MODEL_INFO_PROBE=0` disables the lookup.
- **Cancel keeps history** — stopping a turn mid-reply keeps the request and the partial reply (marked as interrupted) in the conversation, so "continue" or a correction builds on it (Gemini CLI complaint: cancel erases history).
- **Headless signal handling** — SIGTERM/SIGINT/SIGHUP during `oasis -p` cancel the turn, stop running commands and their process groups (previously they outlived Oasis), and exit `128+signal` instead of looking like a success (Gemini CLI headless bug class).
- **Fix-thrash detection** — when edits keep failing a command in exactly the same way (signature ignores timings, numbers and temp paths), the model is told on the 3rd identical failure to stop patching and diagnose, and on the 5th to summarize and change approach or ask; the CLI shows `[stuck?]`.
- **Lean tool loading** — rarely used setup/install/terminal/cron tool schemas are deferred (about 2.7k fewer tokens per request) and load automatically on first call or via `tool_search`. Opt out with `leanTools: false` or `OASIS_LEAN_TOOLS=0`.
- **Change guard** — blocks edits that replace real code with placeholders such as `// ... rest of the code unchanged`, warns on large unexplained shrinkage, and detects fix-circling (reverting to an earlier broken state).
- **Commit secret scan** — `git_commit` builds the commit in a throwaway index and scans added lines for real credentials (API tokens, private keys, `PASSWORD=` style assignments, `user:pass@` URLs). Hits are refused with `file:line` and a masked preview; samples like `AKIA…EXAMPLE` and `process.env` references pass. The same scan runs when the agent types a raw `git commit` (including `-a`/`-am`) through `run_command` or `run_shell`, so the check cannot be sidestepped. Disable with `OASIS_COMMIT_SECRET_SCAN=0`.
