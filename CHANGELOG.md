# Changelog

User-facing change history grouped by package version. A version heading does not imply that a GitHub Release or downloadable assets have been published; check the [Releases page](https://github.com/FAHTHIZ/oasis/releases) for current availability.

## Unreleased

- Two processes on the same session no longer overwrite each other. Resuming a session in two terminals (or the CLI and `oasis web`) used to keep only whichever saved last. A save now checks whether the session file was saved by someone else since this process loaded or last saved it; if so, this conversation is saved as a new session and a note gives its ID, so both stay resumable.
- Browser app, Anthropic: replies are no longer limited to 8,192 output tokens. The default now follows the model (32,000 for Claude 3.7 / 4 and later, 8,192 for 3.5, 4,096 for Claude 3), and a "max_tokens ... > N" 400 is retried once at the reported limit, which is remembered for that model. `outputCapFromError` moved to the browser-safe `src/output-cap.mjs`, shared with the CLI.
- `oasis bg send` no longer cuts messages at 20,000 characters (same 200,000 bound as steering), and the stream-json `permission_request` event carries the whole approval prompt instead of its first 300 characters.
- `ask_user_question`: the user's typed answer is no longer cut at 2,000 characters (now the 200,000-character steering bound), and questions, option labels and descriptions allow 4,000 / 200 / 1,000 characters instead of 600 / 80 / 300.
- PostCompact hooks receive the whole `compact_summary` instead of its first 20,000 characters.
- Compaction summaries are no longer cut. With any must-preserve record set, a summary past about 12,000 characters lost its tail (usually the open work and next steps), the must-preserve block was clipped at 8,000 characters including labels, and mid-turn tool-round summaries were cut at 12,000 characters. All three are now kept whole; the records stay bounded by their own 20-item / 8,000-character limit.
- The CLI and `oasis web` now report a failed session save after idle compaction on stderr instead of ignoring it.
- Browser app: the system prompt's "Top level" list now says how many entries past the first 60 were left out, instead of silently ending the list.
- Steering notes are no longer dropped. When more than 20 undelivered steering messages piled up across turns (or in a saved session), the oldest were silently discarded on carry, save and load; they are now merged into the first carried note, so every instruction still reaches the next turn.
- Waiting for a person no longer uses up a tool's timeout. Approval prompts inside a tool (for example "Run this command?") and `ask_user_question` answers paused nothing before, so a user who took more than two minutes to answer saw the tool fail with "Tool timed out". The tool kernel now pauses its timer while it waits for the user and resumes it with the time that was left; cancellation still works during the wait.
- The tool kernel no longer cuts tool timeouts to 15 minutes (it would have stopped a long `MCP_TOOL_TIMEOUT` call), and a `run_command` given the full 600 seconds now stops on its own timeout, with its output, instead of racing the kernel limit set at the same 600 seconds.
- MCP tool calls follow `MCP_TOOL_TIMEOUT` (milliseconds, as in Claude Code) or `OASIS_MCP_TOOL_TIMEOUT_MS`, up to a day. Every call used to stop at two minutes, and a longer request was clamped to 15.
- A hook's `timeout` is honoured up to a day. It was cut to 600 seconds without a word, so a longer check was killed at 10 minutes.
- `oasis acp`, the Codex app server and the Telegram gateway log a failed session save (disk full, a session over the size cap) instead of dropping the error.
- Browser app: a reply cut off by the output token limit never runs the tool call that was still being written. The model is told the call did not run and to split large writes, and continues a cut-off answer (up to three times per request).
- `/compact preserve` refuses a record over 600 characters with the length and limit, instead of saving it cut off at 600.
- Browser app: a reply stream that ends before the model finished (no `finish_reason`/`[DONE]`, or no Anthropic `message_stop`) is retried instead of being kept as the answer, which could run a half-written tool call. Anthropic authentication and invalid-request errors inside a stream are no longer retried.
- Copying browser chats to the computer sends the whole chat (newest turns first, up to the 4 MiB import limit) and every chat in every project. It used to stop at the last 300 turns, 60 chats per project and 100 projects.
- Browser app: chats are saved whole (they were cut to the last 300 messages and 200 shown entries), and the chat list keeps every chat (it dropped all past 50). If storage is full, the recent part is kept. Chats saved by older versions load without a tool result whose call was cut off, which providers rejected.
- Roo and Kilo mode rule folders: every file is read (the first 50 used to be the limit), and files past the 48 KiB budget are listed by path in the prompt instead of being skipped without a word.
- Saved sessions keep their whole history. A 5,000-message cap used to drop the start of long sessions on save; only the 64 MiB byte cap remains, and a session near it is first written without indentation before any history is trimmed.
- With a fallback model set, an HTTP 529 (overloaded) switches to it right away instead of retrying the overloaded model first. Without one, 529 is still retried.
- An error event inside a streamed reply (Anthropic `overloaded_error`, `api_error`, `rate_limit_error`, `timeout_error`; Responses `server_error`, `rate_limit_exceeded`, `server_is_overloaded`) now restarts the stream instead of ending the turn. Authentication and invalid-request errors stay final.
- search_files searches files up to 16 MiB (was 256 KiB), so large single-file sources such as TypeScript's checker.ts no longer return "no matches". When ripgrep is missing, the fallback grep now says how many files over 1 MiB it skipped, or that it stopped after 8,000 files.
- write_file, write_file with append, and edit_file strings accept up to 64 MiB, the same as editing an existing file (was 256 KiB). Overwriting a file over 256 KiB now keeps its line endings and encoding and runs the elision check; before, those were skipped for large files.
- Security: every hook group for an event is loaded. Before, groups past the 50th were dropped, so a PreToolUse guard there never ran. Plugin dependencies past the 50th were also ignored.
- OpenCode/Kilo commands and agents defined in opencode.json are no longer cut to the first 200, Roo/Kilo custom modes to the first 50, and an @folder mention lists 500 entries (was 200) with a note saying how many more there are.
- Custom agent files (.claude/agents, .oasis/agents, plugin agents and the OpenCode and Gemini formats) up to 1 MiB load. Before, any file over 64 KiB was skipped without a word. An agent prompt over 200,000 characters now ends with a note saying how much was cut.
- MCP: tools/list, prompts/list, resources/list and resources/templates/list follow nextCursor across every page, as the spec allows servers to split them. A repeated cursor or 100 pages ends the listing. Servers are no longer cut to their first 80 tools or 200 prompts and resources, .mcp.json is no longer cut to its first 40 servers, and managed allowedMcpServers/deniedMcpServers lists are read in full (a deny entry past 500 was ignored).
- Every installed skill is found. Before, each skill folder was cut to its first 80 entries in directory order, extensions to 100 (with 240 skills each), Antigravity plugin folders to 40, and the whole list to 240 alphabetically. Skills past those limits could not be loaded at all. The prompt catalogue keeps its character budget and its "N more skills not listed" note.
- Security: settings lists are read in full. Permission deny and ask rules past 500, sandbox deniedDomains past 500, denyRead/denyWrite paths past 200, credential masks past 200, managed deniedModels past 200, skillOverrides past 500 and auto-mode hard_deny rules past 200 were dropped silently, which let the extra entries through. Settings files keep their byte limit. Adding a permission rule or trusting a folder no longer rewrites the list to its first 500 entries, and it no longer drops entries it does not recognize.
- /btw side questions and the advisor see the newest 150,000 characters of the transcript (was 60,000 for /btw) as whole lines, with a note saying how many older lines were left out. The question itself is kept up to 100,000 characters (was 8,000, cut silently). Hook context from SessionStart, UserPromptSubmit, SubagentStart and PostToolBatch, the SubagentStart prompt and the PostToolUseFailure error are now cut from the middle with a note instead of at a silent limit.
- The browser app's provider client follows x-should-retry and retry-after-ms / Retry-After, as the CLI does. A server-advised wait of up to 60 s replaces the fixed backoff, and "false" stops a retry the server says will not help.
- HTTP 529 (Anthropic overloaded) and the Cloudflare origin errors 520-524 are now retried with the patient 5xx backoff. Before, they failed the request on the first reply.
- Provider retries follow the retry-after-ms header (milliseconds, read before Retry-After) and x-should-retry, as the OpenAI and Anthropic SDKs do: "true" retries a status that is not normally retried, such as a 409, and "false" stops retries of a 5xx the server says will not clear.
- Queued messages for the model (teammate messages, finished-agent notices, background MCP results, background hook results) are no longer lost when they add up to more than 20,000 characters. Each request takes up to 100,000 characters of whole messages (20,000 for hook results); the rest stay queued for the next request, with a note saying how many are waiting.
- MCP prompts used as commands keep up to 200,000 characters (was 60,000, cut without a note) and end with a note past that; MCP server instructions over 8,000 characters now say they were cut.
- A Stop, SubagentStop, or TeammateIdle hook's reason reaches the model with up to 10,000 characters (start and end, with a note) instead of being cut at 4,000, and tool hook feedback keeps 20,000 instead of 8,000.
- Hook replies are read whole up to 10 MiB and decoded as a stream. A JSON reply over 64 KiB used to be cut, so its decision (a deny included) was dropped without a word, and non-ASCII text split across chunks came out garbled. A reply over the limit now counts as a failed hook (onFailure: "block" denies). Hook context over 10,000 characters keeps its start and end with a note instead of only the first 2,000 characters.
- Scheduled prompts (cron_create) are kept whole up to 200,000 characters and refused above that, instead of being cut at 4,000. IDE selections keep up to 100,000 characters (was 20,000) and a longer one ends with a note naming the lines to read.
- Custom slash command arguments are no longer cut at 8,000 characters (a pasted log after /fix arrived incomplete), and fenced ```! shell blocks up to 64,000 characters now run instead of staying unrun past 8,000.
- Nested AGENTS.md and CLAUDE.md files, loaded when OASIS works in their directory, share a 100,000-character budget per directory (was 12,000), so an ordinary nested file is no longer cut short.
- Output from git, background processes, ast-grep, gh, auto-test runs, MCP headersHelper scripts, Chrome DevTools and the Codex app-server host is decoded as a stream. Each chunk used to be decoded alone, so a non-ASCII character split across two reads (common in paths, logs and test names) came out as two replacement characters and could break a JSON line.
- Shell output inside custom commands and skills (!`cmd` and ```! blocks) keeps up to 30,000 characters, as Claude Code's Bash output does, with its start and end and a note when it is longer. It used to be cut at 16 KiB with no note, and multi-byte characters split across output chunks came out garbled. Custom command files of up to 1 MiB load (was 64 KiB, silently skipped past that).
- Results of MCP tasks that finish in the background keep their start and end with a note, up to the normal tool-result size. They used to keep only the first 12,000 characters with no note. Specialist review text keeps up to 1,000,000 characters (was 12,000), a subagent's output_schema is sent whole instead of being cut into invalid JSON at 12,000 characters (schemas over 100,000 characters are refused), and steering notes restored from a saved session keep 200,000 characters.
- `oasis import` no longer replaces an mcp.json or .mcp.json that has a syntax error. The destination is now read strictly before the first write, so the import stops with an error naming the file and nothing is changed.
- Adding an MCP server with /add or `oasis add` no longer replaces an mcp.json or .mcp.json that has a syntax error. The file used to be read as empty and rewritten with only the new server; OASIS now stops with an error, as `oasis mcp add` already did. Those writes are now atomic.
- Enabling, disabling and configuring plugins now write settings.json through the same serialized writer as the rest of OASIS, so a plugin change and another settings change made at the same moment no longer lose one of them. An empty settings file is read as no settings instead of an error.
- Plugin commands no longer replace a settings or plugin file they cannot parse. Enabling, disabling or configuring a plugin when settings.json had a syntax error used to write a fresh file holding only the plugin entry, losing permissions, hooks and env. OASIS now stops with an error naming the file. Plugin JSON files of up to 16 MiB are read (was 1 MiB, silently ignored past that).
- Instruction files (AGENTS.md, CLAUDE.md, rules, imports) load whole up to 150,000 characters each and 300,000 in all. They used to be cut at 9,000 characters per file and 40,000 in all, which cut an ordinary AGENTS.md short; files over 160 KiB were skipped and imports over 40 KiB were not imported. Files up to 4 MiB are now read, imports up to 1 MiB, and OASIS warns, as Claude Code does, when one file passes 40,000 characters or several pass 120,000. The browser-only app keeps 150,000 characters of project instructions (was 12,000).
- Messages sent while a turn runs (steers) are kept whole up to 200,000 characters, the same bound as a web chat message. They were cut at 20,000 characters with no note, and the web steer endpoint refused anything over 12,000 characters (or about 32 KiB of body).
- Subagent reports are kept whole up to 1,000,000 characters, with a note if that bound is hit. They used to be cut at 30,000 characters with no note, which also lost the JSON verdict an agent hook writes at the end. Saved reports keep 200,000 characters (was 8,000), and agent definition bodies keep 200,000 (was 30,000).
- Prompt and agent hooks on PreToolUse and PermissionRequest now see the whole tool action. The payload used to be cut at 30,000 characters, so padding could hide the end of a command. File bodies are shortened to head and tail, and an action that still does not fit is blocked instead of judged on a part.
- Security: the auto mode classifier now always sees the whole action. Its prompt was cut at 24,000 characters, so padding in front of a long command hid the end of it, and the classifier judged only the harmless start. Long file bodies are shortened to their head and tail; any other action too large to show in full is asked about instead.
- The browser app takes messages up to 200,000 characters (was 12,000). A pasted log or stack trace was cut in the app and refused by `oasis web`.
- Reopened chats in the browser app and conversations read through the Cursor-compatible API show long messages in full; they were cut at 24,000 characters, as was the final result of a Cursor API run.
- `--append-system-prompt`, `--append-system-prompt-file` and `--from-pr` text is no longer cut at 20,000 characters (now 100,000, the same as `--system-prompt`). `--from-pr` lost most of the pull request diff it had just fetched.
- Long skills load in full. `load_skill` and `read_skill_resource` cut skill text at 24,000 characters with no way to read the rest, though skill files may be 96 KiB. They now return pages that end on a line break, with an `offset` to continue from. `/skill-name` commands and `context: fork` skills get the whole body.
- Fixed: a subagent whose definition lists `skills:` was given the text "[object Object]" instead of the skill.
- `edit_file` and `multi_edit` now edit files up to 64 MiB (was 4 MiB). Lockfiles, SQL dumps and data fixtures over 4 MiB were refused, even after the model had read the part it needed.
- Earlier images stay in the conversation. Only images from the last 4 messages were resent, so a fifth screenshot in a debugging session made the model lose the first one, and each drop broke the prompt cache. Oasis now keeps the newest 20 images, up to 24 MiB of image data, which fits the provider request limits.
- A reply stream that drops mid-response is now restarted up to 5 times (was 2), as Codex does, with a growing pause between tries. `OASIS_STREAM_MAX_RETRIES` (0-20) changes the count. A stream that goes silent is still restarted at most twice, since each stall already waited a full idle window.
- One model message can now run up to 64 tool calls (was 16). Wide read batches went past 16, and the extra calls came back as "Not executed", so the model spent another step asking for them again. At most 10 read-only calls still run at once.
- Long replies now stream in full. The live stream stopped at 24,000 characters, so a long answer (a whole file, a long report) showed cut off in the CLI, over ACP (Zed and other editors) and in the browser app. Streaming now runs to 1,000,000 characters, and the CLI and ACP append any remainder from the final reply.
- `fetch_url` now downloads pages up to 10 MiB (was 1 MiB), as Claude Code's WebFetch does. Long article pages are several MiB of HTML (Wikipedia's "United States" is about 3 MiB) and were refused with "Response exceeds the 1 MiB limit"; they now convert to Markdown in the existing worker, with the same timeout and plain-text fallback.
- `/model --list` and the /model picker no longer drop models from large gateways. The list was capped at 500 models after sorting, and OpenRouter alone lists about 470, so a slightly larger gateway lost every model late in the alphabet (`qwen/`, `x-ai/`, `z-ai/`). The caps are now 5,000 models and 16 MiB.
- Saved sessions now keep the whole conversation. Before, a save kept only the last 120 messages, so resuming after a long agentic turn (60+ tool calls) lost the earlier requests and work; a session over 3 MiB could not be saved at all, and a reply with more than 30 parallel tool calls made the save fail. The caps are now 5,000 messages, 64 MiB and 512 calls per reply, and a session over the size cap is saved with its oldest exchanges dropped instead of failing. Session search reads the same larger files.
- Long model replies no longer fail partway through with "exceeded Oasis's 8 MiB response limit". The limit counted the raw stream, where every token carries 100-250 bytes of envelope, so replies of about 40,000+ output tokens tripped it. The stream limit is now 512 MiB, and a single event is limited to 32 MiB.
- The stream idle watchdog now waits 5 minutes for the first byte after a silence (10 minutes at high, xhigh or max effort), up from 2 minutes. Reasoning models send nothing while they think, so long high-effort steps were cut off, restarted and billed again. `OASIS_STREAM_IDLE_SECONDS` still overrides it.
- Read-only tool calls in one reply now run at most 10 at a time (`OASIS_MAX_TOOL_CONCURRENCY`, or Claude Code's `CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY`, up to 64). A reply with dozens of reads or web fetches used to start them all at once. Results keep their order.
- Telemetry: retries and recoveries (connection retries, 5xx/429 retries, rate-limit waits, stream restarts, malformed tool calls, context overflow and output truncation) are now `oasis.recovery` events on the span they happened in, plus an `oasis.recovery.count` counter.
- Internals: the end-of-turn checks (what happens when the model answers without calling a tool) moved out of the 5,500-line agent loop into `src/completion-gates.mjs`, an ordered gate pipeline with its own tests. Behaviour is unchanged.
- Mermaid diagrams in replies: `stateDiagram`/`stateDiagram-v2`, `classDiagram` and `xychart-beta` blocks are now drawn as text diagrams (by [beautiful-mermaid](https://github.com/lukilabs/beautiful-mermaid), MIT) instead of being shown as source. Flowcharts and sequence diagrams keep OASIS's own renderer. A diagram that would be wider than the terminal, or uses wide (CJK) labels, still falls back to its source.
- `oasis -p --output-format stream-json`: the `init` event now carries the session id (it was `null` until the end-of-run save), as `claude -p` does, so a client can record the id for `--resume` before the run finishes. A run that ends before anything is saved reports `session_id: null` in its result instead of an id that `--resume` cannot find.
- Web app: with the light theme (chosen, or matched from the device) the page no longer flashes dark while it loads. A small classic script in `<head>` (`app/theme-boot.js`) applies the saved theme before first paint.
- Voice replies (web app Talk mode, `/api/speak` and the Telegram, Slack and Discord gateways) no longer read out backticks and code when a model opens a code fence in the middle of a line (`Fixed it. ```js`); the fence is moved to its own line first, so the code is announced as "(code omitted)".
- A command that was denied or blocked (by you, a rule or the auto mode classifier) no longer gets the "You already ran this exact command successfully" reminder. No process started, so the reminder told the model a side effect had been repeated when nothing ran.
- Web app: a step group that opens straight to its only step now folds that step back when a second step joins the group, instead of leaving the first step's inspector expanded for the rest of the run. A step you opened or closed yourself keeps its state.
- OASIS now requires Node.js 22.19 or newer (was 22.15). The terminal renderer, `@earendil-works/pi-tui` 1.5.2, declares `node >=22.19.0`, so 22.15–22.18 passed the installer and `oasis doctor` checks but were unsupported. The installers, `oasis doctor`, `package.json` and the docs agree on the new floor.

- `oasis doctor` wraps long report lines between words with a hanging indent on a terminal (piped output is unchanged), instead of the terminal splitting words such as "openai-comp/atible".
- Shell deny rules now see commands run through GNU `parallel` (`parallel rm ::: x`, `parallel ::: "rm x"`) and through inline git aliases (`git -c alias.y='!rm x' y`); an inline alias that runs a shell command is also always high risk, so `--yes` and broad allow rules still ask.
- The secret shield now keeps «secret:ID» placeholders in `generate_image`, `text_to_speech` and `create_pull_request` arguments instead of swapping in the real value, so a prompt-injected model cannot send a hidden credential to an image or speech provider or publish it in a pull request.
- Read-only command auto-approval no longer covers `jq` filters that use `env`, `$ENV` or `$__prog_args`; they printed every environment variable (API keys included) without asking, while `printenv` and `env` already asked.
- `/help` now word-wraps descriptions under the description column at the terminal width, and the startup hint row breaks between items, so narrow terminals no longer split words such as "lo/sing" or "Shift+Tab/modes".
- Project agent files (`.oasis/agents/`, `.claude/agents/`, `.agents/agents/`, `.gemini/agents/`) are now protected paths: editing them always asks with a warning, because their `hooks` and inline `mcpServers` run when the agent is launched in a trusted workspace.
- Auto-test runs (the `autoTest` setting and `/test`) now run inside the OS sandbox when it is enabled, like `run_shell`; before, they were spawned directly, so agent-written test code could write outside the workspace even with the sandbox on.
- "Could not reach the model provider" now names the host it tried (`at 127.0.0.1:11434`; never credentials or the path), and for a local Ollama port it suggests `ollama serve`.
- Web app: the diff for a changed file now has **Discard**, which, after a confirmation, puts a tracked file back to its last committed version (including a deleted one), like the per-file revert in the Codex app and Cursor. It reads the committed version with `git ls-tree`/`cat-file`, so the repository's filters and hooks never run. It refuses untracked files, symlinks, `.git` and paths outside the workspace, and waits while an agent task is running (`POST /api/workspace/discard`).
- `oasis app-server --listen ws://127.0.0.1:PORT` without `--ws-auth` now says at startup that any local user or process can connect, and suggests `--listen unix://` or `--ws-auth capability-token` for shared machines.
- TUI: input taller than the terminal (for example a 400-line paste) now shows a window around the cursor with "[N more lines above/below]" markers. Before, it filled the screen, and because the frame could not be redrawn in place, every keystroke reprinted it into the scrollback. The text you send is unchanged.
- Permissions: rule and edit-scope globs are now matched by a linear-time matcher instead of a backtracking RegExp. A rule such as `Bash(*a*a*a*a*a*a*a*a*b)` took 3 s on a 40-character command, and grew exponentially with length, so a long model-written command could hang the agent. It now takes milliseconds, and matches are unchanged (checked against the old RegExp on 300,000 random cases).
- CLI: an unknown top-level flag (for example `oasis --modle x -p hi`) now exits with "Unknown option --modle. Did you mean --model?" instead of being sent to the model as the task. Without a terminal, `oasis --bogus` used to hang silently. To send a task that starts with a dash, put `--` before it (`oasis -- "-x is broken"`).
- Web file preview: a missing file now gets "No file named … in this workspace" instead of the raw ENOENT error with the absolute path. The file is read through a handle opened without following a final symlink and re-checked, so a file swapped for a symlink or FIFO after the check cannot be read and cannot hang the request.
- Protected paths: agent edits to project command files (`.oasis/commands/`, `.claude/commands/`, `.gemini/commands/`, `.opencode/commands/`, `opencode.json`) now ask first. In a trusted workspace these commands run their inline shell and grant their `allowed-tools` when you type them, so a prompt-injected edit could otherwise plant a command that runs later without approval.
- Approvals: general prompts (opening the browser terminal, starting an MCP server, leaving plan mode with a plan and others) keep their line breaks, and indented command lines still show as code. They used to be squeezed into one run-on paragraph.
- Routines: the browser workspace now says "The scheduler is running" while `oasis web` hosts the scheduler itself. It used to say the scheduler was not running, because the check skipped this process. A second routine with the same name (case-insensitive) is now refused with the id of the existing one (HTTP 409 in the browser), because duplicate names made `oasis schedule pause NAME` and other name lookups fail as ambiguous.
- Web app: the Task box in Settings → Routines → Add a routine is a full-width field again; it rendered as a small inline box with its label pushed below it.
- `oasis doctor`: the provider line names local servers ("Ollama (this device) at 127.0.0.1:11434"), and a missing `ollama` command no longer reads "not found" next to a working Ollama server: it says the command is only needed to pull models.
- Web app: while `oasis web` pauses sign-ins after too many wrong access keys, the page now says so, keeps the saved key and reloads when the pause ends. It used to fall back silently to the browser-only app ("This browser only", "Paste a key to start"), as if OASIS were not running.
- `oasis web` / `oasis app`: after an update on disk adds a shared module (for example a `git pull` while the server is running), the server rebuilds its list of app files instead of answering 404, which left the page stuck on "Connecting…" until a restart. Rebuilds happen at most every 2 seconds, and only files the app imports are served.
- Web app: Settings names well-known local model servers ("Ollama (this device)", "LM Studio (this device)", "llama.cpp (this device)") instead of showing a raw `127.0.0.1:11434`.
- Web app: diffs (edit approvals, tool cards, the file diff view) now highlight the words that changed inside similar changed lines, as the terminal already did. Both use the same jsdiff-based code, now in `src/word-diff.mjs`.
- Docs: `docs/ARCHITECTURE-ALTERNATIVES.md` no longer lists the removed `src/cloud-task-store.mjs`, and a new test fails when current docs name a repository file that does not exist.
- Internal: `src/tool-kernel.mjs` (the Node adapter for the portable tool kernel) no longer re-exports `TOOL_CAPABILITIES`, `TOOL_RISK_LEVELS`, `validateToolInput` and `evaluateToolPolicy`, which nothing imported from it; `src/tool-kernel-core.mjs` still has them.
- Web app: in Plugins, the "Anthropic plugin marketplace" offer now appears as a bordered row like the others, without a stray list bullet.
- Session search (`session_search`, `/recall`): ranking now uses SQLite FTS5 BM25 through Node's built-in `node:sqlite`, in place of MiniSearch. The index is cached in `<config>/sessions/search-index.sqlite` (mode 0600). Each search re-reads only the session files that are new or changed and drops deleted ones. Session files are unchanged and stay the source of truth, and a damaged cache is rebuilt from them. On 1,000 synthetic sessions of 40 messages each, repeat searches take 25–150 ms instead of about 3 s; the first search, which builds the index, takes about 1.5 s. Ranking on a labelled 15-query set is the same (15/15 top hits). No new dependency.
- Internal: 231 helpers and constants that were exported but only used inside their own module (across `src/`, `app/core/` and the VS Code extension) are no longer exported, and three that nothing used at all (`redactSecretValues`, `FALLBACK_PROVIDERS`, a duplicate alias) were removed. No behaviour change; the `oasis` package entry point (`src/sdk.mjs`) is unchanged.
- Internal: removed exports nothing used (`STEP_KINDS` in the web timeline, the `stringifyYaml` re-export, and duplicate tool-definition re-exports from `power-tools.mjs` and `monitors.mjs`). No behaviour change.
- `oasis web`: when browser packages the app needs are missing (a source checkout updated with `git pull` but not `npm install`), startup now names them and says to run `npm install`. Before, the page sat on "Connecting…" with "No project" and no hint why.
- Keyless web search: the DuckDuckGo and Bing result parsers no longer depend on attribute order or quote style (`href` before `class`, single-quoted or unquoted values), so a markup reshuffle on either site no longer leaves the results empty.

In an empty folder the agent is told to prefer built-in tools (`node:test`, global `fetch`, `unittest`) over new frameworks and config files, then run the program and its tests. ## [1.3.0] - 2026-11-12

### Live runs that tell the truth

- Commands stream their output while they run, and every step reports its real outcome. The timeline's step labels and group titles say "failed" or "denied" when that is what happened, not "done".
- Terminal: a live status line names the running command (short commands only, so long scripts don't flood it), the spinner is driven by a clock, type-ahead is echoed while the agent works, and redraws are synchronized so the screen doesn't flicker. Ctrl+O during a turn expands the newest tool output.
- Terminal: approvals show the proposed diff with clear added/removed styling, and the turn summary leaves out time spent waiting for you.
- Web app: a crisper live run view. Streaming replies are split into finished Markdown blocks and an open tail, so earlier paragraphs stop re-rendering.
- Web app: approve or deny right inside the waiting step. The docked approval sits above the run clock and notes, and the run clock pauses while it waits.
- Web app: notes sent while the agent works keep their look after a reload and no longer offer "Edit and resend". Long chats say when old messages are trimmed and offer Show all. The sidebar refreshes running tasks when the tab comes back.

### More

- `/presets`: ten numbered slots (1-10; `0` is 10) for prompts and `/commands` you send often, like Codex's `/presets`. `/presets save N TEXT` saves (no TEXT keeps your last message), `/presets N` sends it, `/presets clear N|all` empties slots, and bare `/presets` in a terminal opens a picker. Saved per user in `presets.json` (private file mode) next to `config.json`, and `/presets N` works in the web app too.
- Web app sidebar: a task left running in another chat shows "Needs you" when it is waiting on an approval or question, and "Done" in bold once it finishes, until you open it (like the unread markers in Codex's and Claude Code's task lists). `/api/sessions` marks a running session that is waiting with `waiting: true`.

- Web app: opening a running task from the "folder is busy" note (or from another device) always shows the request it is working on, and its steps no longer appear twice when the session was saved mid-turn.

## [1.2.0] - 2026-11-12

### `/rewind N fork`

- `/rewind N fork` (or `/rewind fork N`) saves the whole conversation, then continues in a copy from N turns back, like Hermes's `/rewind fork`. The original stays available with `/resume ID`. Files are left as they are; `/rewind N code` restores them as well.

### `/model NAME EFFORT`

- `/model gpt-5-mini high` switches the model and sets reasoning effort in one command, like Codex's inline `/model` argument. The effort word is one of `low`, `medium`, `high`, `max` or `auto`; anything else stays part of the model name.

### Fixes from real-model testing

- Targeted edits that pass a check no longer trigger an extra "review the diff" round trip and a duplicate summary. The verification gate meant to skip this only did so after a whole-file overwrite had happened earlier in the turn. Whole-file overwrites of existing files are still reviewed.
- Answered approvals in the terminal collapse to one line (`⎿ Allowed once`, `⎿ Allowed for this session: …`, `⎿ Denied`) instead of leaving the full menu in the scrollback.
- Closing `oasis web` (and the SDK's `startOasisWebServer`) no longer waits forever when the background model-catalog download gets stuck; it waits at most 2 seconds. The refresh also stays off inside test runners even when the server is given its own environment.
- Keyless remote endpoints (for example `oasis connect https://text.pollinations.ai/openai`) are priced as free, so the footer shows `$0.00` instead of "cost unknown".

### Cursor Cloud Agents API on `oasis web`

- `oasis web` answers Cursor's Cloud Agents REST API under `/v1` and the legacy `/v0`, so scripts and tools written for it drive OASIS agents on your own computer or server with any configured model. Agents are OASIS conversations in the served folder; runs are agent turns. Supported: creating agents, listing with cursor pagination, follow-ups (`409 agent_busy` while a run is active), steering, cancelling, a Server-Sent Events run stream with `Last-Event-ID` resume, per-run token usage, archive, unarchive and delete, plus models, `me` and repositories. v0 adds the conversation, follow-up, stop and HMAC-signed `statusChange` webhooks. See [Cursor Cloud Agents API](docs/INTERFACES.md#cursor-cloud-agents-api).
- It uses the web server's access key and protections: Bearer, or Basic with the key as the username and an empty password; the same host checks and wrong-key lockout. Approvals still apply to API runs.
- What OASIS cannot do honestly is refused with a 4xx that names the field: opening pull requests, creating branches, PR URLs, other repositories, Cursor cloud environments, `envVars`, inline MCP servers, custom subagents and image URLs.

### Codex SDK drop-in (`oasis exec --json`)

- `oasis exec --json` (alias `--experimental-json`) prints the `codex exec --json` JSONL stream: `thread.started`, `turn.started`, `item.started`/`item.updated`/`item.completed`, `turn.completed` with usage, `turn.failed` and `error`. Items use the Codex exec shapes: `agent_message`, `command_execution` (command, aggregated output, exit code), `file_change` (path and add/update/delete), `mcp_tool_call`, `web_search` and `todo_list`. OASIS tools with no Codex item type are reported as `mcp_tool_call` with server `oasis`.
- The OpenAI Codex TypeScript SDK can run OASIS with `new Codex({ codexPathOverride: '/path/to/oasis' })`: `exec` accepts the flags it sends (`--config key=value`, `--sandbox`, `--cd`, `--add-dir`, `--image`, `--output-schema`, `--thread-source`, `--skip-git-repo-check`), the prompt on stdin, and `resume THREAD_ID` after the flags. Thread ids are OASIS session ids, so `codex.resumeThread(id)` continues the saved session.
- `--config` keys the SDK sets are mapped: `model`, `model_reasoning_effort` (minimal/low → low, xhigh → max), `approval_policy`, `sandbox_mode`, `sandbox_workspace_write.network_access` and `web_search`. Other keys are listed on stderr and ignored. `danger-full-access` with `approval_policy="never"` runs like `--yolo`; OASIS's hard refusals and its inline-code check (for example `node -e`) still apply, so some commands Codex would run are declined and reported as failed `command_execution` items.
- Setup failures (no provider, bad flags) print one `error` event and exit 1, which the SDK raises as an error.

### OpenTelemetry GenAI conventions

- Model-call spans now carry `server.address`/`server.port`, `gen_ai.request.stream`, reasoning level, reasoning and cache-write token counts, and `gen_ai.response.finish_reasons` as a string array (it was a single string). Failures set `error.type` (HTTP status, `cancelled`, Node error code or class).

- `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` switches span names to `invoke_agent oasis`, `chat MODEL` and `execute_tool TOOL`; the `oasis.*` names stay the default. Telemetry is documented in [docs/CONFIGURATION.md](docs/CONFIGURATION.md#telemetry-opentelemetry).

### Routines (durable scheduling)
- Routines accept RFC 5545 recurrence rules: `DTSTART;TZID=Asia/Dhaka:20261127T170000 RRULE:FREQ=MONTHLY;BYDAY=-1FR`. Supported: FREQ=DAILY, WEEKLY, MONTHLY and YEARLY, with INTERVAL, COUNT, UNTIL, BYDAY (with ordinals), BYMONTHDAY, BYMONTH, BYHOUR, BYMINUTE and WKST. A rule that runs out marks the routine completed. Unsupported parts (sub-daily FREQ, BYSETPOS and others) are refused with a reason.
- `oasis schedule` (aliases `oasis cron`, `oasis routines`) adds routines: prompts or shell commands that run on a schedule whether or not a terminal is open. In-session `/schedule` jobs still end with their session. Schedules are 5-field cron with an optional per-routine time zone (`--tz Asia/Dhaka`), `every 2h`, `in 30m`, or an ISO date. `oasis schedule daemon` runs them; `oasis schedule tick` does one pass for a system crontab.
- Each fire runs in a fresh background session (the same tools, permission rules and logs as `oasis --bg`), in the routine's `--workdir`, with its own `--model`, `--permission-mode` and `--skill` list. `--script` runs a command with no model at all.
- Lifecycle follows Hermes Agent's cron: `pause`/`resume` (a slot that came due while paused gets one catch-up run), `run` (an extra fire that leaves the schedule alone), `cancel` (stops only the current run), `remove` (also stops a live run), `--paused` to create a canary, and lookup by name with ambiguous names refused.
- A missed cron slot runs late only inside a catch-up window (half the period, 2 minutes to 2 hours, or `--grace MINUTES`). A slot that comes due while the previous run is still going is skipped, not stacked. A run interrupted by a reboot or crash pauses the routine for review instead of running again.
- Results are saved under `<config>/schedules/output/` and can be delivered to `telegram:CHAT_ID`, `slack:CHANNEL`, `discord:CHANNEL_ID` or an HTTPS `webhook:` with secrets redacted. Output that starts with `[SILENT]` is saved but not sent.
- Before an agent run, missing model credentials, a missing workdir or a missing gateway token mark the routine `blocked_config` once and no model call is made. Scheduled runs cannot create or change routines.
- `oasis web` and `oasis gateway` now run the scheduler themselves (as Hermes' gateway does), so a separate daemon is optional. Only one scheduler runs per config folder; set `OASIS_ROUTINES=off` to stop a server from hosting it. Settings in the browser workspace has a Routines section to add, run, pause, resume, stop and remove routines, and it shows whether a scheduler is running.
- Webhook routines: `oasis schedule add webhook "triage the new issue"` creates a routine that fires when `oasis web` receives `POST /hooks/routines/ID` signed with its secret (`X-Hub-Signature-256: sha256=…`, the GitHub format, or `X-OASIS-Signature`). Unknown ids and bad signatures get the same 401 and count toward the existing lockout. Payloads up to 256 KB are queued (20 at most), wait behind a run in progress instead of being dropped, are saved to a file the run can read (`OASIS_EVENT_FILE`), and reach the agent marked as untrusted data.
- Webhook routines can filter events like Claude Code's GitHub triggers: `--event pull_request.opened --event release` matches `X-GitHub-Event` (or `X-OASIS-Event`) plus the payload's `action`. GitHub's `ping` is acknowledged and never runs. Non-matching events get `200 {accepted:false}` and are not queued.
- Fixed: `oasis schedule edit` could not clear a field (`--tz ''`, `--model ''`, `--workdir ''`).
- Settings → Routines → Recent results shows the last 10 runs of a routine with status, delivery and saved output (`GET /api/routines?runs=ID`).
- Conversation routines (like Codex thread automations): `--from-session ID` starts every run from a copy of a saved conversation, and `--chain` makes each run continue from the previous successful run. The original conversation is never written to, since each run forks it under a new id that the routine records. In a session, the agent's `routine_manage` takes `continue_this_conversation: true`.
- `/schedule durable DESCRIPTION` asks the agent to set up a routine from plain language (like Claude Code's `/schedule`), and `/schedule routines` (or `/routines routines`) lists them. Plain `/schedule CRON PROMPT` still makes a session-only job and now says how to make a durable one.
- Plain calendar schedules: `daily at 09:00`, `weekdays at 9am`, `weekends at 10am`, `every monday at 14:00`, `weekly on mon, wed and fri at 9:15pm`. They compile to cron in the routine's time zone. A bare `9` is rejected as ambiguous.
- Bounded history: each routine keeps its newest 200 run records and 30 days of output and webhook payload files (`OASIS_ROUTINE_HISTORY`, `OASIS_ROUTINE_HISTORY_DAYS`). `oasis schedule prune` deletes finished one-time routines. Browser edits carry the routine's `updatedAt`, and an edit based on a stale copy gets a 409 instead of overwriting someone else's change.
- The agent can manage routines itself with the `routine_manage` tool (list, show, create, edit, pause, resume, run, cancel, remove). Creating, editing, resuming, triggering and removing ask you every time, even with `--yes`, and the prompt shows the schedule, command, folder, permission mode and delivery target. ### Runtime
- The skill list sent to the model stays within its 16,000-character budget by dropping whole lines. Before, a long list was cut mid-description and the model was not told that more skills existed. Now the last line says how many skills were left out and points to `list_skills`.
- `oasis -p` no longer throws away a run that is stopped part-way. A timeout, SIGTERM from a CI runner or supervisor, or a provider failure used to leave no saved session, so the work could not be continued. Once the model has answered at least once the session is saved, and text output ends with `The work so far is saved. Continue it with: oasis --resume ID`. Found while running a 15-minute local-model task under `timeout`.
- `oasis bg stop`, attach and respawn no longer trust a stored PID on its own. On Linux each background run records when its process started; if that PID now belongs to a different program (the run ended and the number was reused), the run shows as interrupted and nothing is signalled. Before, stopping a stale entry could send SIGTERM and SIGKILL to an unrelated program's whole process group.
- `npm test` gives the suite a private home folder (`HOME`, `USERPROFILE`, `XDG_CONFIG_HOME`, `APPDATA`, `LOCALAPPDATA`) with a scratch `.gitconfig`, so tests no longer read a model catalog cached in your real `~/.config/oasis` (which changed expected context windows) or leave backup folders there. Set `OASIS_TEST_REAL_HOME=1` to opt out. `oasis web` now refreshes the model catalog with the environment it was started with.
- `/goal` has the full lifecycle: `/goal pause`, `/goal resume`, `/goal edit CONDITION` and `/goal clear`. Ctrl+C or the turn limit pauses the goal instead of discarding it. Resuming keeps the turn count and the last check, and tells the model not to repeat finished work. Goals are saved with the session; one that was running when OASIS stopped comes back paused. Goals are capped at 4,000 characters.
- Learned skills can improve themselves, like Hermes' `skill_manage`, but still with your approval. When a learned skill turns out wrong or outdated, the agent can call `skill_propose` with `update: true` to propose the corrected version. `/learning show ID` marks it as an update, and `/learning approve ID` replaces the skill and keeps the old version as `SKILL.md.bak`. Updates only touch skills in the learned-skill folders (`.agents/skills`, `~/.config/agents/skills`).
- Memory is bounded the way Hermes does it, without losing notes. A full store (500 notes per scope, or `OASIS_MEMORY_LIMIT`) no longer refuses new ones. It moves the least valuable note to `.archive/`: outdated first, then stale and never recalled. The note stays readable there. Notes marked outdated leave the prompt index but stay searchable, and the index lists the most useful notes first (recalled, verified, recent), so a tight budget drops the least useful.
- `/swarm` (the Kimi Code name) is an alias of `/batch`, which splits a large change into independent units and runs them in parallel worktree subagents.
- `npm run bench:memory` measures memory search on a fixed held-out set: 92% of questions get the right note first and 100% within the top 3 (MRR 0.960). A regression test keeps it above those floors.
- Resuming a long conversation that has been idle for over an hour (30k+ tokens, at least about $0.05 on a paid model) warns that the provider cache has likely expired, says what the next message will cost, and suggests `/compact` or `/clear`. Claude Code added the same warning in 2.1.304. Local and free models never warn.
- OASIS asks before a web, MCP or network shell call sends your own email address (from `git config user.email`, `GIT_AUTHOR_EMAIL` or `OASIS_USER_EMAIL`) over the network, once per address and tool, in every mode except bypass. GitHub noreply addresses are skipped. Claude Code added the same check in 2.1.317.
- A new JavaScript module must be loaded once before the work counts as verified. In a live eval the model created `src/lib.mjs` with a CommonJS `require.main` check inside an ES module; `npm test` passed because nothing imported the file, yet it threw on first use. The verification gate now names any new exporting module that no passing check loaded, and assisted verification runs `node <file>` for it (servers, CLIs and browser code are skipped).
- Read deduplication no longer traps a model that keeps asking for the same file. The first repeat of an unchanged read still returns a short pointer; a second repeat returns the content, since the model has lost track of the earlier result (Claude Code 2.1.317 removed its stub for the same reason).
- A self-paced `/loop` now ends when a run finishes without calling `schedule_wakeup`, instead of waking again after a guessed 10 minutes (matching Claude Code 2.1.319). `OASIS_LOOP_KEEPALIVE=1` keeps the old behavior.
- Deny rules now see commands run through `busybox` or `toybox` applets (`busybox rm x` used to escape `Bash(rm:*)`). Found by a new adversarial policy corpus: 54 inputs that must never match a strict allow rule, 41 spellings that must hit a deny rule, and a wider unbash/tree-sitter parity set.
- `search_files` no longer returns a bare empty list. A query that looks like a regex (`a|b`, `foo.*bar`) is retried as one, and an empty result explains that the search is one literal string and suggests grep, glob_files, list_files, or creating the code if it does not exist yet. In a live eval a small model made five empty searches in a row before writing anything.
- `write_file` and `edit_file` warn when a change mixes module systems: CommonJS `require`, `require.main`, `module.exports` or `__dirname` in an ES module (`.mjs`, or `.js` under `"type": "module"`), or `import`/`export` in a `.cjs` file. The warning gives the ESM replacement, so the mistake is fixed before any test runs.
- Resuming a session whose goal was paused prints `[goal] Paused goal: … /goal resume continues it; /goal clear drops it.`
- Goals work in print mode: `oasis -p --goal "npm test passes"` (or `oasis -p "/goal npm test passes"`) keeps working until a strict check says the condition is met, up to `--goal-turns N` turns (default 10). Stream JSON emits a `goal_check` event after each turn; the result carries `goal: { condition, met, turns, reason }`, and a goal that is never met ends as `error_goal_not_met` with exit code 1, so CI can tell.
- The goal check now reads verdicts wrapped in markdown (`**MET**`, `Verdict: MET`) and never reads "NOT MET" as met.
- Test files that import helpers from `src/cli.mjs` no longer start an interactive session as a side effect; `main()` only runs when cli.mjs is the entry point.
- Running `oasis` with piped or redirected input no longer prints "Oasis session closed." and exits without saying why. It explains that interactive mode needs a terminal, shows the `oasis -p` equivalents, and exits with code 2.

- `npm test` gives each run a private temporary folder and removes it afterwards. Before, a full run left about 4,000 folders and 1 GB (heap snapshots from the `/heapdump` test) in the system temp folder. It also no longer depends on shell globbing, which Windows `cmd` lacks.

In `oasis -p "/command"`, the command's `allowed-tools` were dropped, and its read-only context lines (`git diff HEAD`, `git log`) were skipped. Both now behave as in Claude Code. A compound shell line is allowed when allow rules cover every piece. A commit that fails because Git has no author identity says so instead of blaming hooks.
- `git_commit` tells the model when the work is already committed: the success result says to report the hash, and a repeat call names the earlier commit. A real gpt-oss-20b run made six more commit attempts after the first succeeded.
- In `oasis web`, adding files from the Files panel failed with "workspace.write is not a function". Files now go into the real project folder, including PDFs and other binary documents up to 10 MB, so the agent can read them. Writes stay inside the project, refuse protected paths (`.env`, `.git`, keys) and links, ask before replacing a file, and wait while an agent is running. Verified in the browser: an uploaded report.pdf was read correctly by gpt-oss-20b.
- When a text-only model rejects an attached image ("This model does not support image input"), OASIS remembers that for the session. It resends without the image data, replacing each image with a note, so the model tells you it can't see it. Later messages keep working. Before this, the user saw a raw HTTP 400, and every later message in that chat failed the same way. Found in the browser workspace with gpt-oss-20b. The stored image is kept, so a vision model picked later still gets it.
- An `error` event inside a chat-completions stream now restarts the reply (within the usual restart limit) unless it is permanent (auth, quota, context length, policy, other 4xx). Pollinations sends one when its upstream glitches, and it used to end the whole run.
- Auto mode approves the project's own test, lint and build commands (`npm test`, `node --test`, `node x.test.js`, `pytest`, `cargo test`, `go test`, `make test`) without a classifier call, while the default "Test and build" rule is in force. Seen live: on a free model that takes 45 s per reply, every test run had been denied when the 30 s classifier call timed out.
- The auto-mode classifier's time limit stretches to 1.5x the main model's typical reply time (up to 180 s) when it runs on the same model; `autoMode.timeoutSeconds` sets it.
- A classifier timeout is reported as a timeout, with a hint to set `autoMode.model`, instead of "cancelled by the user".
- A 429 that means "one request at a time" (Pollinations' keyless API) now waits and retries instead of failing in under a second.
- A declined command now tells the model not to retry or ask again, but to finish what it can and name the command for the user.
- Shutting down the browser workspace now waits briefly for cancelled tasks to record their final status, then closes task history, so no write lands after shutdown. This fixes an intermittent cleanup failure on Node 26.
- New `dontAsk` permission mode and `permissions.denyInsteadOfPrompting` setting (Claude Code parity): calls that would wait on an approval prompt are denied with a readable reason and the turn continues, so CI and unattended runs never hang. See [Permission modes](docs/CONFIGURATION.md#permission-modes).
- The SSRF address policy is built on `ipaddr.js` with declarative CIDR tables.
- Plugin downloads, MCP OAuth discovery and public web fetches share one DNS-pinned, size-bounded HTTP client (`src/safe-http.mjs`) instead of three copies.
- The test suite is green on `main` again after the tool-registry and Pages removals.

### MCP
- In `auto` mode, read-only and closed-world MCP tools from your own MCP config run without a classifier call. The server's annotations decide this. Project servers, secret-like tool names and changed tools are excluded. Found in a live run: a free one-request-at-a-time model timed out on the classifier and the tool was wrongly denied. The same run now answers in 49 s.
- Long-running MCP tools run as MCP Tasks through the official [`@modelcontextprotocol/ext-tasks`](https://github.com/modelcontextprotocol/ext-tasks) requester. When a server declares `tasks.requests.tools.call` and a tool sets `execution.taskSupport` to `required` or `optional`, OASIS creates a task, polls at the server's interval, reads the result and sends `tasks/cancel` when you interrupt. Task calls are not bound by the per-request timeout (2-hour ceiling).
- A task still running after 5 seconds moves to the background in the interactive terminal and in streaming headless sessions, as in Claude Code. The turn continues, and the result arrives as a notification that wakes an idle session. It passes through the prompt-injection guard. Interrupting the turn after the move does not cancel the task. Set `OASIS_MCP_TASK_BACKGROUND_MS` to change the grace period. `OASIS_MCP_TASK_BACKGROUND=0` (or `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1`) always waits. One-shot `-p` runs and the browser always wait.
