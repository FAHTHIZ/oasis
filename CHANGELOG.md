# Changelog

This file records notable user-facing product changes. It does not imply that an entry has been published as a GitHub Release.

## Unreleased

Changes after 1.0.0. Every item below came from a miss in the model-free harness benchmark ([docs/BENCHMARKS.md](docs/BENCHMARKS.md#model-free-harness-benchmark-2026-11-01)) and has a regression test.

- Web UI and desktop app: MCP elicitation requests (forms and URLs) now show as an answerable card instead of being silently declined; new `POST /api/jobs/:id/elicitation` endpoint, schema sanitized before it reaches the page, 10-minute timeout.
- Commands that start with a long sleep (10 s or more) are refused before approval, with a pointer to `monitor` or `run_in_background`, as in Claude Code. `OASIS_ALLOW_LONG_SLEEP=1` turns this off.
- Memory: Claude Code's auto memory for the repository (`~/.claude/projects/<project>/memory/`) is imported read-only, so what it learned carries over when you switch to OASIS. Worktrees share the main checkout's memory. `OASIS_IMPORT_CLAUDE_MEMORY=0` skips it.
- Desktop app: uses the operating system's proxy settings (including PAC) when no proxy variable is set, and trusts the OS certificate store alongside Node's bundle, so it works on corporate networks with TLS inspection out of the box.
- `oasis doctor --network` checks the route (direct or proxy), DNS and reachability of the model provider, remote MCP servers and GitHub, without sending credentials, and explains failures such as untrusted certificates behind TLS-inspecting proxies.
- `OASIS_DISABLE_THINK_KEYWORDS=1` (or `CLAUDE_CODE_DISABLE_ULTRATHINK=1`) stops words like "ultrathink" and "think hard" from raising the thinking budget or reasoning effort; configured defaults still apply.
- Corporate proxies: `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY` / `NO_PROXY` now apply to every outbound request (Node's fetch ignored them, so OASIS could not reach a model from behind a proxy). HTTPS goes through a CONNECT tunnel with normal certificate checks, loopback always connects directly, redirects drop credentials across origins, and `oasis doctor` shows the proxy. Desktop app included.
- Unattended runs can wait out rate limits: `OASIS_WAIT_FOR_RATE_LIMIT_MINUTES=N` sleeps until the provider's advertised reset (Retry-After, Anthropic or OpenAI reset headers) when it is within N minutes, then retries, instead of failing the job. Billing errors never wait; the header timeout is paused during the wait.
- Memory: personal instructions from Codex (`~/.codex/AGENTS.md`, honouring `CODEX_HOME`) and Gemini CLI (`~/.gemini/GEMINI.md`) now load as user memory, so switching tools keeps your habits. `OASIS_OTHER_AGENT_RULES=0` skips them.
- **Shell safety sees through nesting.** Catastrophic deletes, force pushes and publishing are now refused when hidden inside `bash -c`, `eval`, `su -c`, `env -S`, `watch`, `find -exec sh -c`, `ssh host '…'`, `$(…)`, backticks, `<(…)`, or inline Python/Node/Perl/Ruby/PHP code. Paths that land on home or root (`~/.`, `$HOME/..`, `"${HOME:?}"`, `~user`, `//`) and `npm --registry x publish` are caught. A commit message or `echo` that only mentions `rm -rf ~` is no longer refused.
- **Exfiltration needs a person.** Sending a credential file (`.env`, `~/.ssh`, `~/.aws/credentials`, `.npmrc`, `*.pem`, …), an environment dump or a secret variable in a request body or URL through `curl`, `wget`, `nc`, `scp`, `rsync` and similar always asks, even in bypass mode, directly or through a pipe. Normal `Authorization` headers to an API are not affected.
- **Untrusted-content guard.** Results from `fetch_url`, `web_search`, `browser` and MCP tools have hidden Unicode tag characters, bidi overrides and zero-width runs removed (the hidden text is shown in the notice), and text that reads like instructions to an AI agent is flagged. After a flagged result, shell and commands need a person for the rest of the turn, in every mode. `OASIS_UNTRUSTED_GUARD=0` or `"untrustedContentGuard": false` turns it off.
- **Jittered provider retries.** Exponential backoff after rate limits and server errors now waits 50–100% of each step, at random, so parallel subagents that hit the same limit don't retry in lockstep. An advertised `Retry-After` is still honoured exactly.
- **Content-Security-Policy for the web UI and desktop app.** The app page is served with a strict CSP: inline scripts are allowed only by their SHA-256 hashes; there are no remote scripts, `eval`, plugins, framing (`frame-ancestors 'none'`) or `<base>` tricks; network access goes only to the OASIS server. Script injected into the page, for example through rendered model output, cannot run or send data out. A headless Chromium run confirmed the page itself raises no violations. The desktop app also refuses `<webview>` attachment.
- **Dictation in the desktop app and Firefox, and a locked-down desktop permission policy.** Where browser speech recognition is missing or broken (Electron has no speech service; Firefox has no API), the microphone button records with MediaRecorder and OASIS transcribes through a new token-protected `/api/transcribe` route with your `/voice` endpoint. The desktop app used to accept every web permission request, Electron's default. Now its window gets only audio-only microphone access, clipboard writes and notifications, on its own origin; camera, location, screen capture, USB, HID, serial and the rest are refused. The page also sends a restrictive `Permissions-Policy`, and macOS builds declare a microphone usage description.
- **Voice dictation.** `/voice on`, then Alt+V to record and Alt+V again to put the transcript at the cursor for editing (Esc cancels). It works with sox, arecord, ffmpeg or your own recorder and any OpenAI-compatible transcription endpoint, including a local Whisper server. It uses Claude Code's `voiceEnabled` setting and `voice:pushToTalk` keybinding. Only user or managed settings can turn it on or choose where the audio goes.
- **See the models your provider serves.** `/model --list` (or `--refresh`) asks the provider (OpenAI-compatible, OpenAI Responses, Anthropic, Ollama, LM Studio, gateways) for its model list, using the same key and gateway headers, and hides anything outside `availableModels`. The `/model` picker includes those models too, waiting at most 2.5 s. Bedrock, Vertex and Foundry say plainly that listing is not supported.
- **Traces follow the OpenTelemetry GenAI conventions.** Turn, model and tool spans carry `gen_ai.*` attributes (operation, provider, model, token usage, tool name and call ID, agent name, conversation ID, `error.type`), and model calls are CLIENT spans, so LLM-observability backends understand OASIS traces without any mapping. Existing `oasis.*` span names and attributes are unchanged.
- **Line-range @mentions.** `@src/app.ts:120-180`, `@src/app.ts#L120-L180` and `@src/app.ts:42` (with 20 lines either side) attach only those lines, numbered, so the part you mean is never cut off by the size limit on a large file. The `@path#L10-20` references that the VS Code extension inserts for a selection now attach just the selection instead of the whole file.
- **Worktree subagents survive restarts too.** A subagent that was working in its own git worktree when OASIS stopped is resumed in that same checkout by `send_message`, with its conversation and its unfinished changes, and its work is committed on its branch when it finishes. Before resuming, OASIS checks that the worktree still exists inside the repository, is on the recorded branch and still contains its starting commit; otherwise it refuses and names the branch. If a resumed worker fails, its worktree is kept for review instead of being deleted. Saved sessions also no longer lose a worktree agent's branch, path and commit when they are loaded.
- **Fewer false alarms from the untrusted-content guard.** Pages that say "You are now logged in" and API docs that say "send the access token in the Authorization header" are no longer flagged (a flag holds risky actions for the turn). Role rewrites ("You are now DAN…") and secrets sent to an outside address are still caught, and sending a `.env` file to an address is now detected too.
- **MCP sign-in resists mix-up attacks.** OAuth sign-in checks the RFC 9207 `iss` parameter against the discovered authorization server and refuses a response from a different server, or one with no issuer when the server promised to send it.
- **`oasis doctor` suggests the sandbox.** When the OS sandbox is available but off, doctor says how to turn it on (`/sandbox on` or `"sandbox": {"enabled": true}`).
- **Desktop app security updates.** Electron 45.1.0 → 45.2.1 (Chromium security fixes in the shipped app) and electron-builder 26.4.0 → 26.18.0, which removes the critical `tar` and the high-severity advisories in the installer toolchain. Production dependencies have no known advisories.
- **Auto mode can't be steered by relayed messages.** Messages from other sessions, background-event prompts and hook notes are no longer counted as your intent by the auto-mode classifier.
- **Head-to-head evals against Codex and Gemini CLI.** `oasis eval --codex` and `oasis eval --gemini-cli` run those agents headless on the same disposable task copies and hidden verifiers as `--claude-code`, record tokens from their JSON output, and produce reports that `--compare` accepts.
- **Better OpenAI prompt-cache hits.** Responses API requests to api.openai.com carry a `prompt_cache_key` (a hash of the session ID, separate per subagent), which keeps a long conversation on the same cache, as Codex does. Cheaper and faster turns. `OASIS_PROMPT_CACHE_KEY=1` sends it to other Responses endpoints, `=0` turns it off.
- **Subagents survive restarts.** Shared-workspace subagent conversations are saved next to the session, so after a restart or `--resume`, `send_message` resumes the worker with its full context instead of failing with "no live worker". Workers interrupted mid-task are resumed with a note to re-check the files first. Saved transcripts are validated on load (no injected system messages, matching agent ID) and removed with the session.
- **Background agents you can steer and recover.** `oasis bg send ID "message"` reaches a running background agent at its next step, like steering in the terminal; late messages become one more turn instead of being dropped. `oasis bg list` shows each agent's latest step. Runs that died without finishing (crash, kill, reboot) are marked `interrupted`, with a boot ID check so a reused PID after a reboot is not mistaken for a live run, and `oasis respawn --interrupted` resumes them all with their conversations.
- **Parallel tool calls.** Requests now let the model ask for several tool calls at once (`parallel_tool_calls` was hard-coded to false, although the executor already ran read-only batches concurrently). Exploring a codebase takes fewer model round trips. `parallelToolCalls: false` or `OASIS_PARALLEL_TOOL_CALLS=0` restores one call per response.
- **Crash-safe settings and state.** The main config, MCP server config, saved credentials, input history, plugin state, workflow state and backup manifests are written atomically, so a crash or full disk mid-save can't leave a truncated file.
- **Sandbox that doesn't break builds.** Existing package-manager caches (`~/.npm`, pip, uv, cargo, Go modules, Maven, Gradle, pnpm, Bun, Playwright and others) are writable inside the OS sandbox, so `npm install`, `cargo build` and `go test` work with the sandbox on. Home stays read-only, symlinked caches pointing outside home are ignored, and credential paths stay masked. `sandbox.writableCaches: false` turns it off.
- **Security check on every edit.** Lines added by `edit_file`, `write_file` and patches are checked, with no model call, for common vulnerability sources: `eval`/`new Function`, shell commands built from variables, `innerHTML`/`document.write`/`dangerouslySetInnerHTML`, SQL built with string formatting, `pickle`/`yaml.load`/`Marshal`/`unserialize`/`BinaryFormatter`/`ObjectInputStream`, `shell=True`/`os.system`, TLS verification turned off, MD5/SHA-1 password hashes, `strcpy`/`gets`/`sprintf`, wildcard CORS with credentials, and hard-coded credentials. The agent gets the risk and the safer alternative and fixes it in the same turn, or explains why it is safe. Tests, fixtures and docs are skipped. `OASIS_SECURITY_CHECK=0` turns it off.
- **Crash-safe edits.** `edit_file`, `write_file`, notebook and patch edits write to a temporary sibling, flush it and rename it over the file, so a crash, kill or full disk can no longer leave a half-written file. File modes, symlinks and hard links are preserved.
- **More secret formats masked.** OpenRouter, Anthropic admin, Groq, xAI, Perplexity, Replicate, Google OAuth (`ya29.`, `GOCSPX-`), PyPI, DigitalOcean, Shopify, Linear, Doppler, Stripe webhook, GitLab deploy/runner, Twilio and Telegram bot tokens, Slack and Discord webhook URLs and Azure storage keys.
- **Steer while it works.** In the terminal and the browser, a message you send during a turn reaches the agent at its next step as a real user message; it acknowledges it, adjusts, and keeps going without losing progress. If the message arrives while the agent is writing its final answer, the turn continues so it is handled. Anything the agent did not get to is sent as the next message, never dropped. Tab (terminal) or Alt+Enter (browser) still queues for after the turn. Subagents never consume the parent's messages. The VS Code chat panel steers too, and stream-json clients can send `"steer":true` on a user line.
- **Turn summary and progress notes.** Each interactive turn ends with a dim `Done · 55s · 4 tool calls · 12.3k tokens` line, and the agent is told to say in one sentence what it is about to do and to post one-line updates at key moments, so you can follow along and steer.
- **Live wait indicator with adaptive motion.** While waiting for the model, the terminal shows what Oasis is waiting on, elapsed time, context sent, the step and `esc to stop`, so a slow model no longer looks like a hang. Motion follows the machine: full on capable hardware, lite on low-power machines, SSH and the Linux console, off for CI, screen readers and `OASIS_REDUCED_MOTION=1`. `OASIS_MOTION` overrides it. The startup logo uses the same rules.
- **Local models get time to read the prompt.** Providers on localhost now wait up to 900 s for the first byte (was 120 s when streaming). On a 2-CPU machine llama.cpp reads about 22 prompt tokens per second, so a 15k-token first request took about 11 minutes and always timed out before. An explicit `OASIS_REQUEST_TIMEOUT_SECONDS` is now honored up to 2 hours; it was silently capped at 15 minutes.
- **Tool results at a glance.** Each tool call now gets a one-line outcome under it: `✓ exit 0 · 20 passed, 0 failed` (test summaries for node --test/TAP, Jest/Vitest, pytest, Cargo and Mocha), `Read 44 lines`, `10 matches in 4 files`, `2 files changed, +6 -1`. Errors and policy blocks are red. Searches show the query, `git_diff` shows as Review Diff.
- **Readable replies and diffs.** Assistant prose word-wraps at the terminal edge with aligned continuation lines instead of splitting words; code blocks and tables are untouched. Diff lines keep code in the normal text color on the tinted background. The verification line reads `✓ Verified · …`, and says "LSP skipped" when no language server ran instead of "0 issues". The banner shows paths under home as `~/…`.
- **`oasis doctor` explains your local model server.** For a provider on this machine it reports which server answered (Ollama, LM Studio or llama-server), the loaded context window, the tool profile OASIS uses for that window, and the exact restart flag when the window is under 32K. On a non-default port it says the runtime will not probe it unless `OASIS_LOCAL_CONTEXT_PROBE=1`.
- **Slow local models no longer fail at five minutes.** Node's built-in `fetch` drops a request whose response headers take more than 300 seconds, and llama.cpp sends none until it has read the whole prompt, so on a laptop CPU long prompts were cancelled at exactly 301 seconds and retried, regardless of `OASIS_REQUEST_TIMEOUT_SECONDS` (found in the llama-server log of a live Qwen3-4B eval). Requests to model servers on this machine now go through `node:http` with no hidden timeout, so OASIS's own first-byte timeout (15 minutes by default for local servers), stream-idle watchdog and Stop button decide. Dropped streams still restart as before. `OASIS_LOOPBACK_FETCH=0` restores the old path.
- **See how far a local model has read your prompt.** With llama-server (llama.cpp), OASIS asks for prompt-reading progress while streaming and the wait line shows it: `Local model is reading the prompt… · 2m 10s · 54% of 7.7k tokens · about 1m 50s left`. llama-server reports once per batch (2,048 tokens, over a minute on a slow CPU), so between reports the line moves on at the measured rate for uncached tokens and never shows 100% before the server does. The browser shows the same line. Checked live against llama-server b12032 with Qwen3-4B; other servers are not sent the extra field.
- **MCP servers over SSE.** `.mcp.json` and `~/.claude.json` entries with `"type": "sse"` now connect instead of being reported as unsupported, using the same headers, `headersHelper` and OAuth sign-in as Streamable HTTP. Replies can arrive on the stream or inline; an endpoint on a different origin is refused, and calls in flight fail with a clear error if the stream drops.
- **`oasis mcp add --transport http|sse NAME URL`.** Remote MCP servers can be added from the command line with Claude Code's syntax, `--header` and `--scope user|project`. Project scope refuses literal credentials in headers (use `${VAR}`), and `oasis mcp login` now also finds servers in the user `mcp.json` and `~/.claude.json`.
- **llama-server is recognized from its overflow error on any port.** When a llama-server on a port OASIS does not probe (for example 8081) rejects the first request as too long, OASIS now records the server as llama.cpp along with the window it reported. The retry uses the compact tool set and later requests show prompt-read progress. No extra requests are sent to unknown local servers.
- **Auto-commit, Aider-style (opt-in).** `/auto-commit on`, `OASIS_AUTO_COMMIT=1` or `"autoCommit": true` commits each turn's changed files as `oasis: <your request>`, leaving other work, ignored files and in-progress merges alone and running your Git hooks. Terminal, headless (`auto_commit` stream-json event) and Web UI.
- **Eval results keep the agent's changes.** Each trial row records the files the agent added, modified or deleted, with bounded contents, for OASIS and Claude Code runs alike. Eval task statements now give each helper's exact signature, so a model is not failed for choosing a different argument order (task fingerprints changed; see BENCHMARKS.md).
- **Smaller prompts for small windows.** The README used as background context is stripped of HTML comments, badges, images and layout tags (all windows), and with a small window only its first 2,500 characters are kept, with a pointer to read the rest. The auto-memory policy is one sentence in compact mode. In this repository the compact system prompt dropped from about 4.5k to 2.6k tokens. When the small window is only discovered from an overflow error, the full system prompt is now swapped for the compact one along with the tools. This also fixes the tool_search note added during that recovery, which was lost at the next step.
- **Skill descriptions written as YAML block scalars are read correctly.** Skills, agents and imported prompts that use `description: >` or `description: |` (the bundled Ponytail skills, and many community Agent Skills) were listed with the description `>`. They now show the real text. With a small context window, each skill is listed by its first sentence only, which keeps the compact prompt at about 1.8k tokens in an empty repository.
- **Codex and Gemini CLI permission flags.** `--full-auto`, `--sandbox`/`-s`, `--ask-for-approval`/`-a`, `--yolo`, `--dangerously-bypass-approvals-and-sandbox`, `--approval-mode`, `--include-directories`, `--cd` and `--skip-git-repo-check` map to the nearest OASIS mode (table in the user guide). Hard refusals still apply in every mode.
- **Start with a task, keep talking.** On a terminal, `oasis "task"` now opens the interactive session with that task as the first message, as Claude Code does, instead of exiting after one reply. `-i`/`--prompt-interactive` (Gemini CLI) is accepted. Scripts without a terminal, `OASIS_ONE_SHOT=1` and `-p` keep the one-shot behavior.
- **Resume without an ID.** `oasis -r` with no ID lists saved sessions (as `claude -r` does), and Codex's `oasis resume`, `oasis resume --last` and `oasis resume ID` map to `-r` and `-c`.
- **Wrong-file check.** When a request says `Create src/lib.mjs ...` and the agent creates a different new file while the named one still does not exist, OASIS tells it once, at the point it tries to finish, to put the code in the named file. Found in a live Qwen3-4B `safe-task-id` run, where the model wrote `src/utils.mjs` and the hidden test could not import it.
- **Aider flags.** `--message`/`--msg`, `--message-file`, `--yes-always`, `--test-cmd` with `--auto-test`, `--no-auto-test`, `--auto-commits` and `--no-auto-commits` work as in Aider, using OASIS auto-test and auto-commit.
- **Codex `exec` flags.** `--output-schema FILE` and `-o/--output-last-message FILE` work with `oasis exec`, so Codex CI scripts run unchanged.
- **Familiar aliases.** `/tokens` (`/context`), `/approvals` (`/permissions`) and `/ask` (read-only `/plan`). `/share` now saves the conversation as Markdown (`/export`) instead of opening a bug report. An alias never shadows a custom command with the same name.
- **`/test`, Aider-style.** `/test [command]` runs the suite (the argument, the `autoTest` setting, or `npm test`). A pass costs no model call; a failure becomes the next task with the output tail attached.
- **`!` shell commands in the Web UI.** Typing `!command` in the browser chat box runs it through the approval-gated terminal job instead of the model, shows the output in the conversation, and attaches it to your next message as context, matching the terminal's `!` passthrough.
- **Dictate in the browser.** A microphone button in the Web UI composer uses the browser's own speech recognition: interim words show as you speak, typed text is kept, and sending stops listening. Hidden where the browser has no recognizer; audio never reaches OASIS.
- **Paste or drop images in the browser.** Paste a screenshot into the composer, drag images onto it, or use the attach button: up to 4 PNG, JPEG, GIF or WebP images, 3.75 MB each, shown as removable thumbnails and in your message. The server checks the declared type against the real file signature, the size and count, and whether the current model accepts images, before a job starts.
- **Notifies you when it needs you.** When a turn that ran at least 15 seconds finishes or stops for approval, the terminal sends a desktop notification (OSC 9 in iTerm2, WezTerm, Ghostty and Windows Terminal; OSC 99 in kitty) or rings the bell elsewhere, including inside tmux. It stays quiet in CI, in pipes and for short turns. `OASIS_NOTIFY=auto|bell|osc|off` and `OASIS_NOTIFY_AFTER_SECONDS` control it. The browser badges the tab title and, if you allow it on your first send, shows a desktop notification while the tab is in the background.
- **Browser workspace polish.** Each step gets its own message bubble instead of later text overwriting earlier updates; replies render as Markdown while streaming; long diff lines wrap inside the card; approval cards show simple commands without extra quoting; the "no language server" note is one short line with the install command. Motion is lite on 2-core/2 GB devices and Data Saver, off with reduced motion, and `?motion=full|lite|off` overrides it.
- **Reproducible web demo.** `scripts/demo/record-web-demo.mjs` drives the real `oasis web` server and UI in a headless browser against a scripted model, including a mid-turn steering message, and writes `assets/demo/oasis-web-demo.*`. It replaces the older browser demo.
- **Reproducible terminal demo.** `scripts/demo/record-demo.mjs` drives the real CLI in a pseudo-terminal against a scripted local model; `scripts/demo/render-demo.py` renders it to MP4, GIF and poster. Output in `assets/demo/oasis-terminal-demo.*`, including the asciicast.
- **Evaluator grows to 50 tasks.** Seventeen repository-level `taskflow-*` tasks on a multi-module CLI project: eight symptom-only bug reports that require a regression test, and nine multi-file features. Verifiers run the full project suite and then hidden assertions. All 50 pass `oasis eval --validate`.

- **Harness benchmark** — `node bench/harness/run.mjs` scores tool-call recovery, edit application, command safety, placeholder and weakened-test guards, secret scanning and context overhead against a no-harness baseline, with a development set and two held-out sets. Results are under `bench/results/`.
- **Shell risk analyzer** (`src/shell-risk.mjs`) — `run_shell` now parses each command line (pipes, `&&`, `;`, subshells, `sudo`/`env` prefixes) instead of matching patterns. Blocked outright: recursive deletes of `/`, `~`, `$HOME`, `..`, home and system directories (including `cd ~ && rm -rf *`), `find … -delete` and `chmod`/`chown -R` on them, raw disk writes, `mkfs`, writes to system files, `shutdown`/`reboot`, package publishing (`npm`, `pnpm`, `yarn`, `bun`, `cargo`, `gem`, `twine`), `gh repo delete`, and force pushes (`--force`, `+ref`, `--mirror`).
- **High-risk commands always ask** — `curl`/`wget` piped to a shell, `git branch -D`, `git clean -x` (ignored files such as `.env` are not in the safety snapshot), `filter-branch`, `reflog expire`, `push --delete`, `docker … prune`, `kubectl delete`, `helm uninstall`, `terraform destroy`, cloud deletes, SQL `DROP`/`TRUNCATE`, `FLUSHALL`, `xargs rm -r`, `shred` and `crontab -r` now need approval even in bypass mode, with allow rules, or inside the sandbox.
- **Tool-call repair** — unquoted JavaScript-style keys, `//` and `/* */` comments in arguments, and calls wrapped in `<tools>`, `<tool_calls>` or `<function_calls>` are recovered.
- **Edit matching** — curly quotes in `old_string` match a straight-quoted file (the replacement keeps ASCII quotes), and spacing drift inside a line (`"a":1` vs `"a": 1`) matches while keeping the file's spacing. Spaces between two words still count, so `return x` never matches `returnx`.
- **Secret scanning** — Stripe-style `sk_`/`rk_` live and test keys and bare `password:` values are caught; an assignment value can no longer run across lines.
- **Guards** — JSX `{/* … */}` and "implementation omitted" placeholders, any short "rest of the styles/props/routes unchanged" comment, Rust `_test.rs` files and `#[ignore]`, and an exact assertion swapped for an existence check (`== 1` → `is not None`, `toBe(1)` → `toBeDefined()`) are flagged.
- **Small local windows** — when the very first request overflows the server's window (llama.cpp: "exceeds the available context size (16384 tokens)"), OASIS reads the size from the error, switches to the small-context tool set and retries, instead of failing. Overflow messages from llama.cpp are now recognised.
- **Repository cleanup** — Beta and release-candidate badge files and the RC1 notes were removed (they remain in Git history and the `v0.4.0` tag); the social preview now says OASIS 1.0.

## 1.0.0 — stable (November 1, 2026)

First stable release. Release notes: [docs/releases/v1.0.0.md](docs/releases/v1.0.0.md). Installers are unsigned and ship with `SHA256SUMS`.

Reliability and token-efficiency work driven by common coding-agent complaints:

- **No unrequested commits or pushes** — `git_commit`, `git_push`, `create_pull_request`, and shell `git commit` / `git push` / `git remote add|set-url` / `git config --global` / `gh pr create` run only when the current request asks for that ("commit", "push", "open a PR", and so on). Otherwise the model is told to leave version control to the user. Found in a live 3B run that committed, set a global git identity, added a remote and pushed. Opt out with `allowUnrequestedGitWrites: true` or `OASIS_ALLOW_UNREQUESTED_GIT_WRITES=1`.
- **Eval runs cannot publish** — the agent under `oasis eval` now gets a credential-free environment, and git pushes from the disposable workspace are rewritten to an unreachable URL.
- **Assisted verification for small models** — on local servers or windows of 32K or less, when the model edits files and then stops without checking its work, OASIS runs the review itself: `git_diff` (or reads the changed files outside Git) plus the detected project test, or `node --check` / `python3 -m py_compile` when there are no tests. Results go back to the model (at most twice per turn). Force with `assistedVerification: true` or `OASIS_ASSISTED_VERIFICATION=1`; `0` turns it off.
- **Give-up and false-claim nudges** — a model that quits after one error, or says it created or changed a file it never touched, is told so and asked to continue. On small or local models, a false claim or a canned refusal ("I'm sorry, but I can't assist with that") is removed from the conversation before the retry, because small models otherwise repeat it, and the reminder names the file from the request.
- **Code-block fallback for weak models** — if a small or local model still pastes the new file as a fenced code block instead of calling `write_file` after a nudge, OASIS writes that block to the new file the request names (new files only, through the normal tool path and permissions, never pseudo-code that "calls" agent tools), then runs the usual checks. Aider-style whole-file editing, limited to the case where it is safe.

- **Tool aliases** — Claude Code style tool names (`Read`, `Edit`, `Bash`, `Glob`, `Grep`, `TodoWrite`, …) and argument shapes map onto OASIS tools; unknown names get did-you-mean suggestions.
- Fixed `oasis skills install` (missing `installSkill`) and the plugin-URL error path in `zip.mjs`.
