# Changelog

This file records notable user-facing product changes. It does not imply that an entry has been published as a GitHub Release.

## Unreleased

Reliability and token-efficiency work driven by common coding-agent complaints:

- **Lean tool loading** — rarely used setup/install/terminal/cron tool schemas are deferred (about 2.7k fewer tokens per request) and load automatically on first call or via `tool_search`. Opt out with `leanTools: false` or `OASIS_LEAN_TOOLS=0`.
- **Change guard** — blocks edits that replace real code with placeholders such as `// ... rest of the code unchanged`, warns on large unexplained shrinkage, and detects fix-circling (reverting to an earlier broken state).
- **Commit secret scan** — `git_commit` builds the commit in a throwaway index and scans added lines for real credentials (API tokens, private keys, `PASSWORD=` style assignments, `user:pass@` URLs). Hits are refused with `file:line` and a masked preview; samples like `AKIA…EXAMPLE` and `process.env` references pass. The same scan runs when the agent types a raw `git commit` (including `-a`/`-am`) through `run_command` or `run_shell`, so the check cannot be sidestepped. Disable with `OASIS_COMMIT_SECRET_SCAN=0`.
- Web workspace redesign (v3 interface): chat-first layout with a collapsible Connections drawer and status chips, new sidebar with search and icon navigation, markdown-rendered replies with copyable code blocks, inline tool-call/result rows, typing indicator, sticky scrolling with "Jump to latest", Enter-to-send composer with history recall and keyboard shortcuts, light theme, and a mobile drawer. Fixed a startup crash (missing stat elements) that made the app open on the dashboard instead of the agent, and added a core bridge so UI layers wrap rendering inside the app closure.
- Web: queue follow-up messages while a turn runs (Enter queues, auto-sends when the turn ends; restored to the box if the turn is stopped), matching Claude Code request #96608.
- Web: the sidebar shows a pulsing dot on chats that are running (including a new chat before it is first saved), hides Delete for them, and refreshes when a turn starts and ends. `/api/sessions` items now include `running: true`.
- Fix: the service worker served app CSS/JS cache-first, so after an update the new page could run with stale styles until the cache name changed. App assets are now network-first with an offline fallback (vendor files stay cache-first).
- Web: finished turns fold their tool steps into a "Worked for … · N tool calls" disclosure (Settings → Appearance → Finished turns), matching Claude Code request #96497.
- Telemetry events include the current git branch (`vcs.ref.head.name`); opt out with `OASIS_OTEL_NO_BRANCH=1`.
- `PostToolUseFailure` hooks can replace the error the model sees (`updatedError` or `updatedToolOutput`), matching Claude Code request #97278.
- Untrusted project settings that set keys other than the safe ones (theme, language, deny/ask rules, etc.) now show up in the "ignored until trusted" notice instead of being dropped silently.
- `oasis sessions prune [--older-than DAYS]` and opt-in `cleanupPeriodDays` / `OASIS_CLEANUP_PERIOD_DAYS` delete stale saved chats (the resumed chat is kept).
- Fixed: nine settings were read by sessions but dropped by the settings loader, so they never took effect from settings files: `fastMode`, `ultracode`, `mcpNonBlocking`, `workflowsEnabled`, `leanTools`, `subagentEffort`, `systemPromptSnapshot`, `teammateMode` and `toolSearchThreshold`. They are now validated and kept (test/settings-keys.test.mjs).
- Subagents can use their own auto-compaction point: `subagentAutoCompactPercent` setting or `OASIS_SUBAGENT_AUTOCOMPACT_PCT`.
- Web workspace: Chat width setting (comfortable, wide, full) and a Send key setting in Settings → Appearance. Fixed: reopened saved chats showed raw markdown (headings, code fences, tables); they now render like live replies.
- Custom model-request headers for gateways: `ANTHROPIC_CUSTOM_HEADERS`/`OASIS_CUSTOM_HEADERS` (`Name: value` lines), provider-config `customHeaders`, and a cached `customHeadersHelper` command (trusted settings or `OASIS_CUSTOM_HEADERS_HELPER`). Reserved headers and the configured API key cannot be overridden.
- One-turn effort: `effort:low|medium|high|max` anywhere in a prompt sets the thinking budget / reasoning effort for that turn only and is stripped before it is sent.
- Worktree branches follow your naming convention: `"worktree": { "branchPrefix": "feature/" }` or `OASIS_WORKTREE_BRANCH_PREFIX` replaces the `oasis/` prefix (validated as a safe ref prefix); inspect, merge and stored task records accept the configured prefix.
- Web workspace: delete saved chats from the sidebar (`DELETE /api/sessions/:id`; running chats are refused), and an optional Ctrl/⌘+Enter-to-send mode (Enter adds a new line), switched by clicking the shortcut hint and remembered per browser.
- Approval prompts now say why a command still asks when an allow rule covers part of it: it uses `$(...)`, backticks, redirects or process substitution (which allow rules never auto-approve), or a piece joined with `&&`/`|`/`;` is not covered.
- Nested `CLAUDE.md`/`AGENTS.md` files that are too large, clipped, or past the nested budget now leave a visible note telling the agent to `read_file` them instead of vanishing silently; oversize `@imports` and oversize rule files are reported the same way.
- Added persistent writing rules: `/avoid PHRASE` (setting `avoidPhrases`; "load-bearing" and "belt-and-suspenders" by default, `OASIS_AVOID_PHRASES=0` to drop them) and `/comments none|minimal|default` (setting `codeComments`, `OASIS_CODE_COMMENTS`). They live in the system prompt so they survive compaction, and with `none` any edit that adds comment lines returns a warning (src/style-rules.mjs).
- Relaxed `edit_file` matches (whitespace/quote-insensitive) now keep the file's curly quotes, dashes and non-breaking spaces outside the changed span, and `write_file` warns when a rewrite silently converts typographic characters to ASCII.
- `run_command`/`run_shell` add a `commandWarning` for flag mistakes that silently do the wrong thing: `rg -r`/`-rn` before the pattern (ripgrep `-r` is `--replace`) and, on macOS, `sed -i` without a backup suffix.
- Added per-session scratch space: `.oasis/scratch/<session>/` is git-ignored, offered to the agent for throwaway files, excluded from the verification gate and pruned after a week (`OASIS_SCRATCH=0` disables it; src/scratch.mjs).
- The browser chat now runs custom commands and skills (`/name args`) like the terminal, and the `/` menu lists every built-in command, custom and plugin command, and skill (new `GET /api/slash-commands`). Fixed the `/` menu collapsing to a thin strip because a stylesheet `bottom` rule fought its script positioning.
- Added the `language` setting, `OASIS_LANGUAGE` and `/language NAME|off` to pin the reply language, so replies do not drift into the language of a file, log or web page.
- Edits to protected configuration files (`.oasis`/`.claude` settings, hook and plugin folders, `.mcp.json`, `.lsp.json`, `.git/`) now always ask with a warning, even with `--yes`, auto mode or broad allow rules (src/protected-paths.mjs). Shell commands that write those paths or set command-running git config keys (`core.hooksPath`, `core.fsmonitor`, `alias.*`, ...) prompt the same way. Deleting a protected file asks with a forced prompt too.
- Added `/mcp reconnect [NAME|all]`: retry MCP servers that failed to start, or restart connected ones, without leaving the session. Fixed: startup MCP failures were cleared after being printed, so `/mcp` no longer showed why a server was missing, and reconnected servers' tools were not added to the session's allowed-tool list.
- Memory now also loads instruction files written for other agents (`GEMINI.md`, `.github/copilot-instructions.md`, `.cursorrules`, `.windsurfrules`, `.clinerules`, Aider's `CONVENTIONS.md`), and identical copies of instruction files are loaded once. `OASIS_OTHER_AGENT_RULES=0` turns the import off.
- Added weakened-test detection: when the agent edits test files, new skips/`.only`/`xfail`/`t.Skip`/`#[ignore]`/`@Disabled`, removed test cases or assertions, and deleted test files (compared with `HEAD`) become a verification blocker that the agent must fix or explain. Reported as `verification.testTampering`.
- Added `oasis exec PROMPT` as an alias for `oasis -p PROMPT`.
- Fixed: headless runs waiting on agent monitors now stop immediately when cancelled instead of waiting for the next monitor event.
- Added `/web URL [--show]` (Aider-style): fetch a public page as text into the conversation, marked as untrusted data. It uses the same public-address checks as `fetch_url` and validates each redirect hop.
- Safety: shell commands that attach to or close apps you have open (COM `GetActiveObject`/`-ComObject`, `win32com`, AppleScript, xdotool/wmctrl/AutoHotkey, `Stop-Process`/`taskkill`/`pkill`, `.Quit()`) always ask with an unsaved-work warning, even under allow rules, sandbox auto-allow or auto mode (prevents the anthropics/claude-code#106370 data loss).
- Added `autoTest` (setting or `OASIS_AUTO_TEST`): after the agent edits files, OASIS runs your test command itself and feeds failures back until they pass (default 3 attempts). It runs as a deterministic step outside the model, is ignored in untrusted project settings, and is reported in `verification.autoTest`. Also fixed `describeTool` dropping the `run_command` detail branch (`if` that should have been `else if`).
- Added `oasis watch`: leave a comment ending in `AI!` (change) or `AI?` (question) in any file and OASIS acts on it when you save; plain `AI` comments add context. Ignored and secret files are skipped, pre-existing comments and the agent's own edits do not re-trigger.
- Docs: release checklist and project-plan snapshot updated with the first all-green SHA (`8ebb5ce`: Quality, installers, desktop packaging, site); security-audit checklist items for navigation-guard E2E, descendant cancellation and adversarial URLs ticked with test references; 0.4.0 notes list the new guardrails, repo map, Web UI v3 and browser fix.
- Fixed: command-palette search never split multi-word queries (the regex was double-escaped), so "chat new" found nothing.
- New: opt-in `"repoMap": true` setting / `OASIS_REPO_MAP=1` adds a focused repository map to the first turn of each conversation.
- CI: `npm test`/`npm run check` now run `test/*.test.mjs` explicitly. Bare `node --test` also executed `test/helpers/clean-lsp-server.cjs` (a stdin server that never exits) and an archived eval snapshot test, so the Node 22/24/26 quality gate hung until its 10-minute timeout.
- Safety: desktop automation (`wmctrl`, `xdotool`, `ydotool`, `cliclick`, `nircmd`, AutoHotkey), `tmux`/`screen` kill commands, container teardown (`docker`/`podman` `stop`/`kill`/`rm`/`down`/`prune`, volume removal) and `kubectl` mutations are now high-risk and always ask, addressing reports of agents closing a user's open app or wiping container data. Read-only and build/run commands are unchanged.
- Web UI: topbar Terminal/Changes/Tasks buttons are only highlighted while the agent view shows that panel; the permission select no longer clips in split view; the Extensions importer keeps URL, destination and button on one row.
- New: `repo_map` tool and `/map` command: a ranked map of source files and their top-level symbols (with line numbers) so the agent can orient itself in an unfamiliar codebase without reading whole files. Ranking favors modules referenced by many other files; `focus` pulls given files/symbols to the top; budgeted output degrades to file headers. 15+ languages via line patterns, no native dependencies.
- Fixed: the `browser` tool blocked every navigation after the first page load ("main frame could not be identified safely") because the `Page.frameNavigated` handler read CDP params as the frame. Denied top-level navigations now answer 204 so the page stays put instead of turning into a Chrome error page. New live Chrome E2E `test/browser-navigation-e2e.test.mjs` covers same-origin, cross-origin link/form/redirect, opaque targets, denial and approval.
- Tests: new cross-platform `test/process-tree-cancel.test.mjs` (cancellation, timeout and SIGTERM-ignoring grandchild with inherited pipes) and the adversarial URL suite now run on Linux, macOS and Windows in the Quality Checks matrix.
- Security: hostnames with one or more trailing dots (`localhost.`, `metadata.google.internal..`) are normalized before the local/metadata blocklist in fetch, browser, plugin-download and MCP OAuth guards; `fetch_url` also blocks `*.internal` and `*.home.arpa`. New `test/url-adversarial.test.mjs` covers alternate IPv4 spellings, IPv4-mapped/NAT64 IPv6, mixed DNS answer sets, schemes/credentials, unfollowed redirects with pinned DNS, and provider failures.
- README: demo recording (GIF + MP4), real quick-start commands, and a "Why OASIS" table mapping common coding-agent complaints to the guards that address them. Restored the "Local only by default" token-safety note in Connections, a 390px phone layout, the first-run error state, and updated `scripts/check-site.mjs` to the v3 design so `npm run check` passes again.
- Fixed: a missing built-in language server (e.g. no `typescript-language-server`) was reported as a blocking "LSP 1 issue(s)" because the detection regex was double-escaped and never matched. It is now shown as "skipped: no language server installed" and no longer blocks completion; the required project check still applies.
- **Live working-tree diff in Changes** — the browser Changes panel now shows uncommitted workspace changes (tracked and small untracked files, per-file +/− counts, click a file to focus its diff) from a new authenticated `GET /api/workspace/diff`. Secret-looking files (.env, keys, credentials) are listed as hidden and never sent to the browser. The panel refreshes when a run finishes and the top-bar Changes button shows a file count. The chat header now adapts to its own width in split view, and long activity rows no longer get squashed in long chats.
- Browser E2E updated for the chat-first layout (opens on the agent, Overview still reachable); fixed faint-text contrast below WCAG AA, a fade-in animation that made new rows briefly fail contrast checks, a "Jump to latest" button that layout shifts could reveal, and made the conversation log, code blocks and side panels keyboard-focusable. Top-bar panel buttons support arrow-key navigation; system notices before the first message now show inside the empty state instead of hiding the starter prompts.
- **`/compact undo`** — compaction (manual or automatic) keeps the pre-compaction history in memory; `/compact undo` restores it, keeping any messages added since. Undo is refused after a rewind or clear past the compaction point so it cannot resurrect discarded history.
- **App-closing commands need approval** — `taskkill`, `tskill`, `Stop-Process`, `xkill`, `osascript`, and `fuser -k` are classified high risk like `kill`/`pkill`, so the agent cannot silently close an application the user has open (the PowerPoint data-loss report, anthropics/claude-code#106370).
- **No silent instruction truncation** — oversized CLAUDE.md/AGENTS.md/OASIS.md/rule files now end with a visible `[... truncated ...]` marker (so the model knows to `read_file` the rest), the CLI prints an `[instructions]` warning at startup, files too large to load are reported instead of skipped, and README.md only uses whatever budget the real instruction files leave.
- **Rule refresh and branch rules** — hard rules (`NEVER`/`ALWAYS`/`MUST`/`DO NOT` lines) from CLAUDE.md/AGENTS.md/OASIS.md are restated after compaction and every ~60k characters of history, so long sessions stop drifting from them. Branch rules such as "Never commit directly to main" or "Do not push to master" are enforced: `git_commit`, `git_push`, and raw `git commit`/`git push` through `run_command`/`run_shell` are refused on the protected branch (subagents included). Disable with `OASIS_RULE_REFRESH=0`.
- **Notebook change guard** — `notebook_edit` now refuses cell sources containing elision placeholders (`# ... rest of code unchanged ...`) and warns when a replacement guts most of a cell, matching the guard on `edit_file`/`write_file`/`multi_edit`.
- **Compact task schema** — the `task` tool lists each subagent type with a clipped description (220 chars) and caps the list at ~3 KB, naming the rest, so projects with dozens of custom agents no longer pay tens of KB of schema on every request. Every agent stays selectable.
- **No more hung commands** — `run_command` and `run_shell` children get a non-interactive environment: `GIT_PAGER`/`PAGER=cat`, `GIT_EDITOR`/`EDITOR=true`, `GIT_TERMINAL_PROMPT=0`, `GIT_SSH_COMMAND=ssh -o BatchMode=yes` (unless you set one), `GH_PROMPT_DISABLED`, `DEBIAN_FRONTEND=noninteractive`, `PIP_NO_INPUT`. `git commit` without `-m`, `git log`, and clones that want a password now fail fast instead of hanging until the timeout. Interactive terminal sessions are untouched; opt out with `OASIS_NONINTERACTIVE_ENV=0`.
- **Standing corrections** — telling the agent to "stop saying 'load-bearing'" now sticks: the ban is restated every turn (immune to compaction), saved to user memory for future sessions, and enforced — a final reply that still uses the phrase is sent back once for a rewrite. Code spans are ignored, and coding rules like `never use "var"` are not mistaken for phrase bans. Preset with `avoidPhrases` in settings.
- **No-op edit check** — when the agent edits through `sed -i`, `perl -pi`, or an inline Python/Node/Ruby `.replace(...)` script, the files it names are hashed first; if the command exits 0 but nothing changed, the result carries a `noOpEditWarning` telling the agent the pattern did not match and to use `edit_file` instead of claiming the change. Opt out with `OASIS_NOOP_EDIT_CHECK=0`.
- **Retry guard** — the same failing `run_command`/`run_shell` call with no successful file edit in between gets a reminder on the 3rd failure (explain the cause, change something, use a non-interactive form) and stops the turn on the 5th, even when timestamps make each output differ. Successful edits, including scripted `sed -i` edits, reset the count.
- **New files are readable** — `write_file` used to create every new file owner-only (`0600`), which broke static files served by nginx, Docker images run as another user, and shared checkouts. New files now get normal umask permissions; only secret-looking paths (`.env*`, keys, credential files) stay `0600`.
- **Unrequested summary docs** — creating an uppercase summary/report file such as `FINAL_SUMMARY.md` or `IMPLEMENTATION_NOTES.md` that the user did not ask for returns a warning telling the agent to put the summary in its reply and delete the file.
- **Partial-read overwrite guard** — `write_file` now refuses to overwrite an existing file the agent has only read part of (a ranged or truncated `read_file`), naming the lines it saw, and asks it to read the whole file or use `edit_file`. A ranged re-read of a file already seen in full does not trigger it.
- **Subagent effort** — subagents can run at their own reasoning effort: `effort: low|medium|high|max` in an agent file, `OASIS_SUBAGENT_EFFORT` (or Claude Code's `CLAUDE_CODE_SUBAGENT_EFFORT`) for all of them, or `"subagentEffort"` in settings. Cheap explorers no longer inherit an expensive main-session effort.
- **Context-overflow recovery** — when the provider rejects a request as too long for the context window (`prompt is too long`, `context_length_exceeded`, HTTP 413, …), OASIS now compacts earlier turns and in-turn history, squeezes old tool outputs, clips an oversized newest output if needed, and retries (up to twice) instead of ending the turn with an error. The CLI and web UI show a one-line notice; hooks see `context_overflow` as the StopFailure type if recovery fails.
- **No silent `-p` hang on open stdin** — with a prompt on the command line, `oasis -p` waits up to 3 s (`OASIS_STDIN_WAIT_SECONDS`) for piped input to start, then continues without it and says so on stderr. CI runners, IDE tasks and `nohup` jobs that inherit a never-closing stdin no longer hang forever with no output; slow pipes that start within the window are still read to the end.
- **No orphaned background commands** — `run_shell`/`run_command` background processes (dev servers, watchers, `tail -f`) used to keep running, and holding ports, after OASIS exited because they live in their own process group. They are now stopped on exit, SIGTERM and SIGHUP (terminal closed); set `OASIS_KEEP_BACKGROUND_ON_EXIT=1` to keep them.
- **Fixed: importing `power-tools.mjs` first crashed** with `Cannot access POWER_TOOL_DEFINITIONS before initialization` (circular import). Tool schemas now live in an import-free `power-tool-definitions.mjs`, so every module can be imported on its own.
- **Edit big files** — `edit_file` and `multi_edit` now work on files up to 4 MiB (was 256 KiB, the single-read limit), so generated code, large bundles and long data files can be changed in place after a ranged read instead of being rewritten by shell scripts. A 3 MB / 40 000-line file edits in ~50 ms.
- **Package vetting (slopsquatting guard)** — `install_package`, and `npm/pnpm/yarn/bun add|install`, `pip/uv/poetry` and `cargo add` run through `run_command`/`run_shell`, look each name up on npm, PyPI or crates.io first. Names that do not exist are refused; near-misses of popular packages (including swapped letters), packages first published under 30 days ago, or with under 50 weekly downloads always need a human confirmation, even in auto-approve modes. Offline checks never block. Disable with `OASIS_PACKAGE_VETTING=0`.
- **Git safety snapshots** — before `git checkout .`, `git restore`, `git switch --discard-changes`, `git checkout -f`, `git stash drop/clear`, `git rm`, and shell deletions (`rm`, `unlink`, `find -delete`, `xargs rm`) run, the full working tree including untracked files is saved under `refs/oasis/safety/` without touching your index or stash; the tool result includes the one-line restore command. Disable with `OASIS_GIT_SAFETY=0`.
- **Stop on fatal account errors** — a 429 that really means out of quota/billing/account on hold is no longer retried, and loops, cron prompts and background wake-ups pause after an authentication or billing error until you send the next message.
- **Honest workflow status** — workflows whose agents failed inside `pipeline`/`parallel` now report the failed count, names and errors (`failedAgents`, `warning`, `partial` in `/workflows`) instead of a plain "completed".
- Fixed a FileChanged race: an unlink that happened while a hook ran could be dropped when the hook returned `watchPaths`.
- **Question budget** — at most two `ask_user_question` prompts per turn by default; further questions are answered with "pick a sensible default, state the assumption, keep working" so long runs are not stalled. Configure with `maxQuestionsPerTurn` or `OASIS_MAX_QUESTIONS_PER_TURN` (`off` removes the cap).
- **Claim check** — if the final reply says tests/build pass but the latest check in that turn failed, was piped (masked exit status) or is stale after later edits, the agent is sent back once to rerun and report the real outcome.
- **Test-weakening check** — edits to test files that remove assertions, add `skip`/`xit`/`@pytest.mark.skip` markers or always-true asserts are reported back to the agent, which must fix the code instead or tell the user why the test changed.
- **Compaction deadline** — the summary request is bounded (`OASIS_COMPACT_TIMEOUT_SECONDS`, default 90) and falls back to a local summary; a "Compacting…" notice shows while it runs.
- **Tolerant edit matching** — `edit_file` and `multi_edit` recover from CRLF, trailing whitespace, smart quotes and indentation drift, and give a closest-match hint instead of a bare "not found".
- **Read dedup** — unchanged re-reads return a short pointer instead of the whole file again (`readDedup: false` / `OASIS_READ_DEDUP=0`).
- **Follow-up ledger** — deferred TODOs the agent mentions are captured in `.oasis/followups.json`; manage with `/followups [all|done ID|drop ID|clear]`.
- **Secret shield** — credentials in tool output are masked as `«secret:ID»` placeholders before reaching the model and restored only inside tool arguments (`secretShield: false` / `OASIS_SECRET_SHIELD=0`).
- **Pipe-masked exit warnings** — `cmd | tail` style commands that hide a failing exit status are flagged so "tests pass" claims are not based on a masked result.
- **Background watchdog** — `max_seconds` for background commands, stuck notices after `OASIS_BACKGROUND_STUCK_SECONDS` (default 300) without output, and fixed missing exit notifications for background `run_shell`.
- **`/scope` lock** — restrict edits to given paths (`OASIS_EDIT_SCOPE`) to stop edits beyond the requested scope.
- **Stream watchdog** — long streams are no longer killed by a 120s whole-request timer; idle streams are detected (`OASIS_STREAM_IDLE_SECONDS`, default 120) and can trigger the fallback model. `OASIS_REQUEST_TIMEOUT_SECONDS` overrides the timeout.
- **Tool aliases** — Claude Code style tool names (`Read`, `Edit`, `Bash`, `Glob`, `Grep`, `TodoWrite`, …) and argument shapes map onto OASIS tools; unknown names get did-you-mean suggestions.
- Fixed `oasis skills install` (missing `installSkill`) and the plugin-URL error path in `zip.mjs`.

## 0.4.0 — prepared Beta version (not yet published)

- Expanded the local-first coding workspace across CLI, browser, editor integration and desktop packaging.
- Added or extended multi-provider setup, optional cost-aware model routing, local Ollama/gateway paths and explicit provider verification.
- Improved agent workflows with subagents, task coordination, task checkpoints, isolated worktrees, run monitoring and safer recovery records.
- Expanded MCP, skills, hooks, native plugin packages and workflow automation.
- Strengthened permission boundaries, command-risk handling, URL and DNS validation, secret redaction, bounded storage/output, process-tree cleanup and post-edit verification.
- Improved installer resolution so supported installers select an immutable stable versioned commit rather than a moving branch.
- Added evaluation report comparison and strengthened fixture validation/quarantine controls.

**Release boundaries:** this version remains Beta. Desktop installers are unsigned; automatic desktop updates and publisher provenance are not configured. There is no native Android APK. The 33-fixture evaluator is not a representative repository-scale coding benchmark. See [the v0.4.0 Beta notes](docs/releases/v0.4.0.md) and [project plan](docs/PROJECT_PLAN.md).
